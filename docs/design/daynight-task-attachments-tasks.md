## 共同完成条件与文件交接

每项任务是一个独立交付目的，保留自身可审查的范围。所有执行者共享该任务的唯一
worktree，修改前检查已有工作；依赖按任务安装一次，探针、数据库和生成证据使用
任务 `.tmp/`，完成验证后清理所属进程及资源。

每项任务同步其影响的现有需求、设计、决策记录和模块 README；根 README 继续拥有
仓库交付状态、文档入口和验证命令。涉及 CLI 产品代码时遵守既有包版本规则。文档必须
区分拟议行为与已经通过的验证，模拟响应、单元测试或本设计 PR 均不能证明真实服务交付。

| 共享位置 | 唯一编辑归属与交接 |
|---|---|
| 服务启动、配置及依赖装配 | A-T1 建立本地存储实例，并同步所有既有启动调用方的必填配置和测试目录；验收完成后 A-T2 接管附件服务及路由装配 |
| 服务 API DTO、错误映射和路由 | A-T2 统一维护；CLI 与 Web 从已交付接口消费 |
| CLI API 客户端、命令登记、输出运行时、语法和补全 | A-T3 统一维护，保留现有 project/task/review/update 行为 |
| Web API 类型、任务详情与公共样式 | A-T4 统一维护 |
| 根 package、锁文件及共享构建文件 | 只有实际需要变更时才修改；A-T3 先完成所需变更，再交接 A-T4，之后交接 A-T5/A-T6；其他任务提出所需输入，不并发编辑 |
| 部署文件、验收启动器与 CI | A-T1 先维护新必填配置所需的 Compose、镜像目录权限、进程启动器和测试 fixture；A-T5 再接管附件持久卷及部署验收，完成后交接 A-T6 的跨层验收和 CI；各任务保留正确模块选择 |
| 本任务页与 Daynight | 文档维护范围和验收；当前负责人使用准确 observed version 更新 Daynight，必要 PR 合并后才完成任务，A-T6 汇总最终证据 |

保留现有 Node.js、pnpm、Go 和 PostgreSQL 版本及检查路径。Go 交付运行
`packages/daynight-server/scripts/check.sh`，使用隔离 PostgreSQL，保留 build、vet、race、
go-cov 的 package/function/critical-block 门槛和未舍入总语句覆盖率严格大于 90% 的要求。
CLI 保留原生平台、安装和真实 shell 补全检查；Web 保留类型检查、生产构建、功能测试和
严格总语句覆盖率门槛。CI 选中的检查必须真实成功，新增附件验收不能取代已有门禁。

FA11 的现有验证要求和 FA12 的范围限制贯穿全部任务。文件与 PG 更新不具备原子性是

台账、扫描或恢复流程，也不把跨 PG/文件回滚作为完成条件。LocalStorage 对单次正常
写入提供完整文件替换，其行为测试与跨存储事务保证分别判断。

## A-T1：通用文件存储

Daynight task：`dfde4b32-ca02-41f1-b4ec-71211fe12cd5`。前置：设计交付。

### 文件归属与范围

负责拟建的 `packages/daynight-server/internal/filestorage/` 接口、`local/` 实现、对应测试，以及
`cmd/daynight-server/`、`internal/server/config.go` 和依赖装配中所需的存储实例配置。
模块只理解 bucket 和相对路径，task 归属及 PG 元数据留给 A-T2。
同时负责因新必填配置而必须修改的既有启动调用方：localhost/dev-ci Compose、
生产镜像中的可写根目录、Web 验收启动器、Go 子进程测试及现有 CLI 真实服务验收。
这些改动只提供有效配置、目录权限和隔离临时根目录；A-T5 继续拥有附件持久卷和
完整部署行为。同步服务模块 README、服务设计及架构设计中的存储配置说明。

### 完成条件

- 按架构提供 `Put/Open/Delete`，调用方使用 bucket 和真实相对路径；实现中没有 task
  专用模型、每次上传的唯一对象 key、版本记录或 bucket 管理 API。
- LocalStorage 使用 `<root>/<bucket>/<logicalPath>` 布局；未来采用前缀分片时只能
  改变本地布局，不能改变接口地址或业务路径。该任务不交付分片配置或迁移工具。
- 流式写入、读取、取消和关闭保留真实错误；成功写入后能打开完整内容，同路径写入
  替换当前文件，读取不会得到写入一半的内容。临时文件只服务于单次写入。
- 真实临时目录测试覆盖多个 bucket 隔离、嵌套路径、覆盖、删除、二进制内容、取消、
  非法路径、越过根目录及实际存储失败。读取、写入和删除均不能通过磁盘路径逃逸。
- 真实根目录验证 `A` 与 `a` 可分别读写，不能相互覆盖；根目录不支持大小写区分时
  以配置错误拒绝启动。测试使用所属目录验证，不更改系统文件系统设置。
- 配置不合法或存储根目录不可用时明确失败；启动和关闭仍由现有运行时持有。
  引入必填配置的同次交付更新全部既有调用方与 fixture，不等待 A-T5/A-T6；真实
  服务启动、既有 Web 验收及两套 Compose 启动保持可运行，临时目录由所属测试清理。
  按实际影响运行服务、Web 和 CLI 检查，保留严格覆盖率。

## A-T2：Task 附件 HTTP 资源

Daynight task：`3c9094f2-9873-4058-b6f1-ae56a2d20470`。前置：A-T1。

### 文件归属与范围

负责 `packages/daynight-server/api/` 的附件 DTO、`internal/core/` 的附件模型、
`internal/core/store/` 的迁移与元数据访问、`internal/service/` 的附件用例，以及
`internal/server/` 的文件和预览路由、请求解析、响应和错误映射。
A-T1 完成后接管依赖装配中的附件服务连接。同步服务需求、服务设计、模块 README
和附件架构中的 API 说明。

### 完成条件

- 一张附件元数据表保存 task 归属、相对路径和架构规定的属性，`(task_id, path)` 为主键，
  不增加独立附件 ID 或 foreign key。使用 `task-attachments` bucket 和 `<taskId>/<relativePath>`
  访问内容，不保存独立存储 key。
- 提供附件分页列表、单文件 PUT/GET/DELETE，以及固定同源
  `GET /api/v1/projects/{projectId}/tasks/{taskId}/preview/{path...}`。
  列表使用 path keyset 和归属绑定的 opaque cursor；创建、覆盖、删除和不存在结果
  遵守架构的状态码与响应格式。
- 每次请求只操作一个文件。相同完整路径覆盖，不同目录的同名文件共存；目录由路径
  隐式产生，文件与目录前缀冲突明确失败。路径中的中文、空格和 URL 编码正确往返，
  非法或越界路径在发生文件操作前被拒绝。
- 校验 project/task 归属，附件操作不改变 task 状态、依赖、版本或更新时间。
  上传和内容响应采用流式传输，保留取消、原始字节、实际内容长度及正确内容类型；
  HTTP 错误继续使用现有 requestId、脱敏和日志规则。
- 预览路由保留文件层次，HTML 的相对 CSS、JS、图片和数据请求映射到同一 task
  的对应文件；HTML 按可信项目代码同源执行，不引入预览会话或 Service Worker。
- 真实 PostgreSQL 与 LocalStorage 测试覆盖列表、创建、覆盖、删除、归属错误、路径
  冲突、内容往返及明确的存储/数据库失败。失败可以留下已记录的内容与元数据不一致，
  测试不把跨存储原子性作为保证。现有服务检查和严格覆盖率通过。

## A-T3：CLI 附件命令

Daynight task：`ab731d8d-668f-44aa-8094-e9603abf2981`。前置：A-T2。

### 文件归属与范围

负责 `packages/daynight/src/commands/task/` 的附件子命令、`src/api/` 的二进制请求
和响应、`src/commands/server/runtime.ts`、`src/cli/context.ts` 所需的流式支持，以及对应
`test/`。统一拥有命令登记、共享语法、帮助、Bash/zsh 补全及其实际 shell 验证改动。
同步 CLI 需求、CLI 设计、包 README、命令示例与包版本。

### 完成条件

- 提供 `task attachment put/list/read/remove`；各命令沿用现有 `--project` 选择与
  仓库关联发现。`put` 接受单个本地文件和可选 `--path`，省略时使用 basename，
  目录参数明确失败。
- `list` 支持默认文件列表、`--tree` 和互斥的 `--json`，读取完整分页；续页失败明确报错。
  命令语法、帮助和静态补全覆盖附件操作及选项，帮助继续不触发业务依赖。
- `read` 直接向 stdout 输出原始字节，不添加标签、转义或换行；诊断只写 stderr。
  CLI 的现有结构化输出不再包裹内容流，二进制数据可通过重定向逐字节保存。
- 上传和下载处理背压、取消、超时、输出关闭及传输错误；失败非零退出，写操作不
  自动重发。读取失败时已输出内容可能不完整，命令文档明确该行为。
- 命令测试覆盖默认和显式 project、路径编码、目录拒绝、覆盖、分页失败、任意字节、
  空文件和传输中断；验证二进制通道不受 JSON 字节上限截断，而元数据仍执行原有
  字节预算。真实 shell 验收覆盖新增语法。现有 typecheck、test、build、
  安装与补全检查通过；真实 Go/PostgreSQL 安装联调由 A-T6 记录。
