# 任务依赖追踪与详情阅读任务拆分

状态：设计完成，待实现。交付目标以[要求](../spec/daynight-task-inspection.md)为准，机制见[设计](daynight-task-inspection.md)，最终交互见[原型](mockups/task-inspection/index.html)。本文拥有每项任务的目的、范围及验收划分；实际状态、任务 ID 和前置关系以 Daynight 为准，前置关系只保存在 `dependsOn`。

## 交付清单

| 标识 | 独立交付目的 | 要求 | 预计工作量 |
|---|---|---|---|
| UX-T1 | 完整展示任务链所需的全部上游上下文 | TI1、TI2 | 60–100 分钟 |
| UX-T2 | 在稳定画布中追踪任务依赖路径 | TI3、TI4、TI5 | 140–220 分钟 |
| UX-T3 | 在居中浮层中阅读任务详情 | TI6、TI7 | 70–110 分钟 |
| UX-T4 | 用 Markdown 阅读和维护任务描述 | TI8–TI11 | 100–160 分钟 |

估算包含实现、受影响文档、独立审查和本地验证；远端 CI、评审和排队的实际等待另计。执行时一次推进一项任务，各自完成受影响的真实验收，不设置承接基础正确性的独立收尾任务。创建任务不授权开始实现，也不授权合并或主线推送。

## UX-T1：完整上游上下文

### 方案

调整 `projectRoot`，保留根及全部后续作为链内主体，对主体递归展开前置闭包，将额外节点作为外部前置；显示所有前置关系，排除外部前置的无关后续。`rootProgress`、聚合状态和项目统计保持原有计数语义。同步节点外部上下文文案、图例、工具栏计数和初始视口，保证根左侧的外部前置可访问。

本项交付投影，不改变卡片打开详情的操作、连线路径算法或描述呈现。同步投影决策、看板要求/设计、生产组件原型与受影响的验收说明。外部上下文变多时仍保留完整内容及既有容量预算。

### 验收标准

- `A → D`、`B → C → D`、`C → X` 中展开 A 显示 A/B/C/D，排除 X；链内计数仍为 A/D。
- 多级外部前置、菱形、共享和已完成依赖均完整去重；图中边集覆盖所有显示任务的前置关系。
- 工具栏区分链内任务和外部前置，图例和可访问名称不再写“上游已省略”。
- 桌面和 320px 下可通过初始视口、平移、缩放及键盘访问全部节点；原有根排序、展开偏好、过滤和独立任务行为正确。
- 受影响模型、布局、组件与生产浏览器检查通过，保留现有容量矩阵，补充外部祖先密集场景的真实测量。

## UX-T2：稳定画布中的依赖追踪

### 方案

将图内依赖选择与详情资源选择分离，卡片主体与“详情”为兄弟原生控件。主体点击和键盘激活切换选择，高亮全部祖先及依赖边，包括箭头与外部虚线。打开详情及内部关系切换不改变图的依赖选择。选择随当前画布生命周期和成功快照更新，不持久化。

保留 Dagre 路由点并使用有界二次曲线圆角化，形成单一标准路径模型。长外部虚线继续使用局部直线与短曲线路径绘制，按实际曲线弧长保持 5/4 相位。高亮只改变样式，路径、布局和视口稳定。同步独立几何判断器及负例，不以生产生成器验证自身。

本项的详情入口调用当时已有详情外壳，不改变它的呈现位置；居中外壳由自己的任务交付。同步当前选择、绘制、性能和键盘文档与决策，更新生产组件原型。两个卡片控件都保留键盘聚焦离屏节点时的可见性处理。

### 验收标准

- 单链、菱形、多根共享、跨链祖先及已完成前置中，选中任务、全部上游及其连线准确同步；根无前置时仅标记自身。
- 点击同一卡片或空白处清除，点击其他卡片替换。Tab 可分别到主体与详情，Enter/空格执行对应动作；没有嵌套交互元素。
- 切换选择、打开/关闭详情、关系切换前后，节点位置、标准路径 `d`、图视口不变；刷新删除所选节点后清除选择，失败保留旧快照。
- 平滑转弯、箭头方向/颜色、虚线连续性及节点避让通过独立判断；缺边、错误 marker、穿节点曲线和相位偏差的负例会失败。
- 严格 Web 检查及原生/容器/容量浏览器验收通过，保留完整工作负载、五次展开、3,000ms/300ms 预算及关闭详情后立即缩放的序列，新增选择反馈测量。

## UX-T3：居中任务详情

### 方案

将现有详情阅读外壳整理为 `TaskDetailDialog`，采用设计中的居中尺寸、视口边距和内部滚动。保留 PR、附件、完整文本、关系、元数据、局部错误与快照差异提示。所有已有打开详情的回调继续调用同一外壳；图内独立入口可用后自然接入，独立任务条目仍直接打开。

复用 portal、共享滚动锁、inert、焦点循环和分层 Esc，保留框架卸载阶段与恢复焦点阶段的既有区分。同步详情、全屏、附件 frame 生命周期文档和生产组件原型。图内选择和独立任务/任务链标签分类不归本项。

### 验收标准

- 1440px 和 320px 下窗口相对可用视口居中，符合 960px 宽度上限和 24px/12px 边距，高度不超过可用视口，页面无整体横向溢出。
- 长内容仅在内容区及代码/表格局部滚动，关闭控件持续可访问；加载、失败、重试、空内容和快照变化提示可用。
- 关闭按钮、遮罩及 Esc 正确关闭，背景不可操作，Tab 在详情内循环，关系切换不重新恢复旧焦点。
- 普通图和全屏图均正确打开与恢复焦点；Esc 先关闭详情，再退出全屏。刷新移除入口、画布卸载及附件 HTML/PDF frame 不遗留锁或 inert。
- 受影响组件及真实原生/容器浏览器检查通过；若独立任务标签已集成，验证条目直接打开同一居中详情和条目消失时的焦点回退。

## UX-T4：Markdown 任务描述

### 方案

提取共享 Markdown 渲染视图，描述按 CommonMark/GFM 展示，使用任务附件根解析相对 URL；附件 Markdown 继续使用文档目录。描述普通相对附件链接复用详情内唯一附件控制器，选中已有预览，保留真实 href 与浏览器原生特殊点击。完整清单、路径和预览错误保持可见，切换 task 或关闭时取消读取。

同步仓库发布源中的 `using-daynight` 入口与模式指引、skill 需求/设计及 README，明确 Markdown 问题描述和已确认附件链接的写法。一个主 Markdown 附件继续拥有方案、验收和执行证据。API/CLI 原始字符串、完整替换字段及版本控制语义保持一致。同步看板、附件 Markdown 文档、相应决策和生产组件原型。

### 验收标准

- 标题、列表、代码、引用、表格、链接、中文长文本及空描述正确显示；原始 HTML 按文本呈现，代码/表格局部滚动。
- `[方案与验收](plan.md)`、`[交互原型](mockui/index.html)` 和相对图片从当前任务根解析；附件文件内的相对引用继续以文档目录解析。
- 普通无 query/hash 的相对附件链接在当前详情中选择并聚焦预览；修饰键、非主键、绝对 URL、fragment 和 query/hash 保留设计定义的 URL 行为。
- 加载、清单失败、缺失附件、非法上越路径、内容失败以及切换 task 后旧响应均有正确行为；不重复建立附件控制器。
- CLI 写入/读取保留原始 Markdown 字节，实际 npm 包含同步后的 skill 全部资源，frontmatter、相对链接、create-task/run-task 行为及安装后内容验证通过。
- 受影响 CLI/Web 检查及真实服务/浏览器描述与附件引用路径通过；现有主附件所有权和独立附件写入语义保持正确。
