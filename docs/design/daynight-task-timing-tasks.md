## ET-T1：持久化任务最后一次执行时间

### 单一目的与归属

让任务执行时间成为跨服务端、CLI 和 Web 读取器一致的事实，为实时展示提供同源时钟。
实现由 `009_task_timing.sql`、core/store/service/API 起止投影、现有生命周期写入和图数据库 `observedAt` 构成。
CLI/Web 类型、严格解析、夹具与有关资源文档同步保留必填可空起止值；图缓存比较排除顶层 `observedAt`，
独立 `GraphSnapshot.observedAt` 仍保留每次响应的最新样本，保证图/索引复用不会冻结后续计时来源。
不加入项目设置或产品计时界面。

### 验收

- 新建、approve、claim、complete 及普通编辑遵守 TT1–TT2；拒绝的状态或版本请求不留下时间变化。
- 迁移前已有任务保持未知历史；数据库时间在项目锁获取后的写 statement 产生。
- 相同低层状态写入保留起止，真实新进入替换起点，不累加；不新增公开重开或直接完成路径。
- full task 与 graph 字段、数据库 `observedAt` 和实际安装 CLI JSON 读取一致；无客户端补默认值。
- 相关迁移、锁等待、回滚、生命周期、快照与读取器验证通过，满足该 PR 必需 CI、独立 review 和平台合并条件。

## ET-T2：交付项目执行提醒阈值

### 单一目的与归属

让项目管理员保存一个项目级执行提醒阈值，并使成员从服务端读取同一设置。
机制由项目列迁移、settings 投影、PATCH、锁后权限检查与独立设置版本构成；
CLI/Web 在 Project、列表与图中无损读取嵌套版本，Web 定向 envelope 解码保持通用未知嵌套语义，
图缓存用 bigint 安全的 Project 指纹分离任务索引。Web 设置同级路由、导航、双语表单保留已保存/草稿状态。
这些部分共同构成一个完整可使用的设置能力；计时卡片留给 ET-T3。

### 验收

- 新旧项目默认均为 60 分钟，保存、跨客户端读取、重启与项目隔离符合 TT3。
- 成员可读、管理员可写；非成员隐藏，锁等待后的移除或降权不能保存。
- 正确版本同值不增加版本或修改 project.updatedAt，过期同值冲突；真实变化递增设置版本并更新 updatedAt，并发更新只产生一个胜者。迁移保持历史项目时间。
- 严格输入校验、未提交/取消草稿和明确拒绝不应用本地值；冲突后重新读取权威 Project 与成员。
- 网络、协议或 5xx 导致未确认写入时先核对再允许新修改；核对失败阻止 Save 并提供读取重试，不重放 PATCH，也不以 abort 宣称回滚。
- 超过 `2^53` 的嵌套设置版本在 Project、列表和图中保持精确；设置到达后图可加载，设置变化不重建任务索引。
- 设置页的权限变化、请求取消、忙状态、双语、窄屏及错误恢复通过适用验证；该 PR 独立完成必需 CI、review 和合并。

## ET-T3：呈现任务实时耗时与卡住提醒

### 单一目的与归属

使用已经交付的任务时间、数据库时钟和项目设置，在任务视图中呈现执行进度与可能卡住的提醒。
交付页面所有的单个时钟与时钟消费者、耗时格式、图卡片及独立任务行展示，复用 ET-T1/ET-T2 已建立的图缓存身份边界，
同步有关 Web、任务和当前设计文档。执行原目标的完整消费者验收，不扩展生命周期或引入服务端告警作业。

### 验收

- TT4–TT5 的实时、冻结、未知、严格阈值和双语视觉均匹配 mock，保留当前 Details、检查、展开、焦点与卡片几何。
- 时钟推进和设置变化不重建任务索引或布局；后台恢复、项目切换、卸载及失效请求清理有效。
- 确定性时钟验证 59:59、60:00、60:01；真实服务与生产 Web 验证实际阈值跨越、改变阈值后的重新判断、complete 后冻结且移除提醒及未知旧记录。
- 结合实际 CLI、隔离数据库和设置权限/失败/冲突，验证原目标全部 TT1–TT6，而非仅组件快照。
- 每个必要 PR 平台确认合并，任务主方案记录可读取的来源与验收证据后才 complete。
