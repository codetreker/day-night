# 固定鉴权架构与执行资料

## 方案

交付[需求](../../spec/daynight-auth.md)、[架构](../daynight-auth.md)、
Daynight 中的实际任务及其附件、英文架构决策和
[最终样式交互原型](../mockups/auth/index.html)。设计覆盖 UniAuth 一次性身份、
本地用户、项目 admin/member、邀请、会话/PAT、可信同源附件预览和统一启用。

设计文档与任务资料使用同一合同，保留既有本机实现的准确状态。旧项目归属后续手工
处理；零成员自然不可见。任务描述保存问题和真实附件引用，方案与验收由本主附件
及各实现任务的主附件拥有；服务中的 dependsOn 是前置关系唯一来源。

前端原型提供登录、项目列表、成员、邀请、个人令牌及预览的可操作状态；资源全部
随附件上传，纯前端可运行。独立审查检查架构可实施性、权限遗漏、并发、同源附件
和各任务完整性。估算 120–180 分钟，用于文档、原型、审查和登记。

## 验收标准

- 需求 AU1–AU12、验证 AU-V1–AU-V10 和架构的身份/授权/预览/部署规则一致；当前实现
  与拟议实现分开，相关活跃文档入口同步，原始决策的历史理由保留。
- 独立设计审查没有未解决的 Critical/Major；重要产品建议与已确认范围清楚可辨。
- 原型在桌面与 390px 窄屏可交互，关键状态、对话框/键盘/焦点与复制失败有验证，
  相对 CSS/JS/其他资源可读取，浏览器控制台没有未处理错误。
- 每项执行任务有一个可读的 Markdown 主附件，包含“方案”“验收标准”；涉及前端
  的任务含可运行原型及全部资源。读回核验任务字段、真实附件内容和 dependsOn。
- 文档本地链接、锚点、note 生命周期/必填章节、新文件和 git diff --check 全部通过。
- 必要设计 PR 经平台确认合并后方可完成本任务；PR URL/title 使用任务属性记录。
  未合并时保留 todo/in_progress，不能把文档准备完成当成已交付运行时。
