# 交付 Web 登录与项目协作界面

## 方案

按[架构](../daynight-auth.md)和[最终样式原型](../mockups/auth/index.html)实现新的
认证 Web 壳、私有项目创建表单、账户令牌页、项目成员面板及邀请接受页。负责 `packages/daynight-web/src`
相关组件、API 类型/请求、样式与浏览器验证。使用实际组件的独立 fixture 验证，
正式主入口切换与后端启用由统一接线完成，不发布半认证的数据入口。

登录壳从 /me 取得身份；项目请求 404 与全局 401 分开处理，切换账号清除旧数据。
项目名称/仓库地址表单复用现有创建 API，成功后展示空项目和创建者 admin。
成员界面基于当前服务角色显示管理操作，提交观察版本；冲突重新取权威状态。
PAT 与邀请秘密只在创建时展示；复制失败保留可恢复操作，关闭前提示一次性秘密。
邀请 fragment 立即清除并以 tab 内临时状态跨登录，明确确认才接受，结束后清理。

复用现有布局、图、抽屉和可访问性，覆盖原型的全部相关状态，不增加任务字段编辑。
附件继续使用现有可信同源 iframe、相对资源和键盘桥；会话失效采用普通错误与登录
提示，没有预览独立凭据或续期流程。估算 180–300 分钟。

## 验收标准

- AU4–AU10、AU-V8 的可见行为与原型一致，使用实际组件完成登录态、成员、邀请、
  令牌和预览流程；所有 HTML/CSS/JS 原型资源随任务附件完整可读。
- 桌面/390px、长名称、空、加载、服务失败、401、404、成员版本冲突、失效邀请、
  PAT 单次显示/撤销、复制失败和禁用管理动作均验证。
- 新账号加载不闪现前账号项目或附件，失败不变空列表；浏览器原生资源、错误返回与
  登录恢复不会出现 iframe 内登录 HTML。原有同源资源和键盘桥继续有效。
- 原有项目列表、图容量与链浏览偏好、抽屉 Tab/Esc/焦点恢复继续通过，生产样式不依赖
  mock controls，控制台无未处理错误。
- Web typecheck/test/build、严格覆盖率和真实浏览器验证通过；更新文档、清理资源，
  必要 PR 合并后完成。
