# 验证完整多人鉴权链路

## 方案

按[需求](../../spec/daynight-auth.md) AU-V1–AU-V10，在已启用的真实服务上补齐最终
跨目标和对抗组合回执。负责 Go/CLI/Web/部署组合验收及源码绑定证据，不替代统一
启用必须具备的安全测试。视觉和交互继续符合[原型](../mockups/auth/index.html)。

使用两名用户、两个部分共享项目、admin/member、邀请、浏览器会话和安装 CLI PAT，
共同读写真实任务与附件。原生及容器目标都执行浏览器登录/预览、CLI 单文件二进制、
角色撤销、重启持久化及秘密日志检查，保留现有默认预算和清理所有权。

扩展未认证/非成员的直接资源访问、过期/重放、同邮箱不同身份、会话切换和已准入
传输撤权组合。可信 HTML 继续按当前浏览者权限执行，不增加沙箱或独立预览授权。
使用实际 UniAuth 与真实上游的人工联调记录单列；受控 provider 证据不代替它，缺少
人工环节时保留未满足项。
估算 120–240 分钟。

## 验收标准

- 每个 AU-V 条目映射到实际场景、固定源码/运行镜像、结果与资源清理证据，至少
  包含原生和容器生产浏览器及真实安装 CLI 使用同一服务数据的完整旅程。
- 未认证/非成员访问、错误 Origin、资源路径、会话失效和成员撤销按合同拒绝；
  可信同源 HTML、脚本/模块/相对资源、HEAD/下载及详情对话框键盘仍可用。
- real DB 竞争、真实文件 IO、网络中断/领取后断连和重启持久化有直接观测，不把
  单元 mock、投影平台或构建成功当作对应 end-to-end 证据。
- 现有完整质量、容量与原生平台门禁仍通过；失败先定位原因，未经证明的基础设施
  问题不重跑。清理只处理任务拥有的进程、浏览器 profile、数据库、卷和临时文件。
- 真实上游登录和配置后的部署联调有独立记录；如果需要用户完成实际登录，该验收项
  保持未满足，不能标记全部完成。
- 必要 PR 均由平台确认合并，主附件保留 PR/merge commit 和验证定位后才完成任务。
