# 建立项目成员授权模块

## 方案

按[架构](../daynight-auth.md)增加成员、邀请及项目准入的 store/service 模块，提供
同一读取快照/项目写事务中可使用的授权原语。负责新增 membership/invitation 迁移、
角色与观察版本、管理员条件、邀请 handlers 和真实 PG 并发验证。生产现有业务入口
的 Principal 参数统一接线留给正式启用，不能加入无身份适配器或复制任务业务。

项目角色只有 admin/member；Principal 只有 session/PAT，附件复用同一主站身份。项目创建
所需的首位 admin 插入与成员过滤 SQL 可在真实事务中验证。列表先筛成员再分页。
成员管理锁项目并重查 admin/观察版本；最后一名管理员的删除/降级拒绝。

邀请固定七天、只授予 member、单次消费、可撤销，属于项目。创建者离任不自动作废。
接受遵循项目→邀请锁顺序；已有成员不消费，不按邮箱猜用户。inspect 仅返回最小项目
摘要。旧项目不自动归属，无成员关系按同一查询不可见。估算 180–300 分钟。

## 验收标准

- AU5–AU9 与 AU-V3–AU-V6 的数据库/handler 行为验证；同一事务创建项目和首位 admin，
  失败不残留半个项目或成员。
- 两名用户在部分共享项目中，分页结果不泄露非成员项目；所有授权原语明确要求
  Principal，不提供匿名或可信身份旁路。
- 两名 admin 并发降级/删除仅一个成功，始终保留 admin；过期成员 version 返回冲突，
  task.version 和现有领域约束不变。
- 邀请 GET/inspect 不入会；并发接受只新增一人；重复、到期、撤销、已有成员及
  创建者离任符合合同，秘密只保存摘要且日志不泄露。
- 零成员旧项目自然拒绝，读取在原快照内、写入在项目锁内检查，IO 准入不持锁传输。
- 服务 gate、严格覆盖率、失败/取消和资源清理通过；保持未挂载模块状态并同步文档，
  必要 PR 合并后完成。
