# Worker 需求

本文定义 `daynight worker run` 的目标行为与可观察验收条件。运行时尚未实现；[架构](../design/daynight-worker.md)说明机制，[交付任务](../design/daynight-worker-tasks.md)拥有拆分及 Daynight task 引用。

## 目标与范围

Worker 作为前台常驻进程，通过 Daynight HTTP REST API 领取配置仓库中可由 Agent 执行的 ready task，使用专用 Herdr 服务运行 Copilot 或 Codex，持续完成任务交付。每个未完成 task 保留自己的 worktree，进程或机器重启后继续原工作。

服务端拥有任务资格、身份权限及唯一 claim；worker 拥有调度、执行资源、恢复与最终完成核验；agent 完成任务要求的交付循环；Herdr 拥有 agent 终端和会话。认证与审批式生命周期是独立前置，不由 worker 再实现一套。

本需求来源于 Goal `555a7772-ad35-40f5-b9d6-ff7dd4e08165`。自动执行许可 task 为 `82bafb30-5c47-4b42-8e78-bb5b524c2ba4`，执行平台 task 为 `4dbd624e-5b16-494b-b12d-8ae7db069ca1`；其附件拥有对应交互原型。实时状态以 Daynight 为准。

## 必须满足的行为

### W-01：前台运行、配置与平台

- `daynight worker run` 与现有 `review run` 一样在前台运行，支持 Linux、macOS 和 Windows。
- 配置支持多个仓库的地址与本地路径；路径不存在时由系统克隆准备，已存在路径须核对仓库身份并保留已有工作。冲突或身份不明确时显示错误。
- 配置包含覆盖全部仓库的最大并发，以及全局默认 agent、模型、参数和仓库覆盖值。Worker 在启动或重启时加载配置，不进行热重载。领取时冻结有效执行配置；继续、重试及重启恢复沿用该配置，重新加载的配置作用于后续新领取任务。
- 配置明确指定工作区或项目内的绝对 `worker.stateDirectory`，保存本 worker 的 SQLite、锁、日志、Herdr 数据和临时资源。启动前校验实际 Herdr 端点路径；路径长度等条件不满足时提示修正配置，不静默改用用户目录。
- 实际平台使用 `windows`、`linux`、`macos`。WSL 中的 Linux worker、Herdr 和 agent 属于 `linux`，不允许通过配置冒充其他平台。

### W-02：Agent 自动执行许可

- Task 具有独立的布尔字段 `allowAgents`，表示是否允许 worker 自动领取并交给 Agent 处理。它与用户身份、项目权限、实际执行者及 agent 类型独立。
- 旧任务通过数据库迁移设为 `true`，保留其余业务数据、版本与时间；新任务始终默认为 `false`，创建输入不能直接启用。普通字段更新未提供此字段时保留原值，显式 `false` 表示关闭。
- 服务端、CLI 和 Web 一致支持许可的查询、展示与明确操作。自动 worker 和随包 Agent 工作流不得自行启用许可。
- Web 在任务详情标题下的状态行右侧提供单一“自动执行” / “Automatic execution”标签与开关组合，左侧保留状态、ready 与可选平台信息。详情不重复展示独立自动执行状态 badge 或下方 Overview 开关；列表中的状态标记可保留。长标题与窄屏不得重叠或横向溢出；平台等左侧信息可在左组内换行，右侧组合控件保持右对齐并与第一行状态顶部对齐。错误、未知结果、锁定和等待人工输入的说明在该控件附近呈现。开启和关闭都先弹确认框，确认按钮直接提交修改；取消、Escape 或关闭弹框均不提交。提交期间阻止重复操作，服务端确认成功后才更新开关；明确失败保留原值，未知结果先读取核对，不自动重发。
- 修改沿用已认证用户的项目成员写权限、精确版本与普通 task PATCH。确认表达明确操作意图，session 或 PAT 不能证明操作者是物理人工；不另设处理角色操作或重复确认字段。
- `allowAgents` 与审批、撤回审批、ready 和依赖独立。开启不批准任务，批准或撤回审批均保留许可。未开启许可的任务仍可由人工明确安排，通过普通 claim 执行。
- `in_progress` 期间拒绝实际切换，完成或合法人工解除 claim 后才允许改变。精确版本的同值更新不修改版本或时间；旧版本同值请求仍拒绝。等待人工输入保留许可，关闭许可不隐式停止或移交执行。

### W-03：可选执行平台

- Task 可要求 `windows`、`linux`、`macos` 之一；未设置表示任意支持平台，新旧 task 默认均不限制。支持明确清除要求。
- 服务端、CLI 和 Web 一致支持设置、清除、展示及必要筛选。已 claim 时与自动执行许可一并锁定，完成或合法人工解除后才可修改。
- 平台条件不改变 task 的 ready 语义，不匹配的候选不占名额、不创建资源、不消耗恢复次数。
- 自动执行许可、ready 与平台条件须在有界候选排序和分页前组合，不能让较早的未开启许可或不兼容任务遮住后续合格任务。

### W-04：原子领取与执行归属

自动领取必须同时满足：

```text
allowAgents = true
AND ready
AND (requiredPlatform is unset OR requiredPlatform = worker platform)
AND no active claim
```

- 服务端在同一事务中重新核验当前自动执行许可、平台、状态、依赖、精确版本与归属，覆盖查询和领取之间的变化。
- 同一 task 跨用户、机器和 worker 只有一个有效 agent claim。竞争失败方不得启动执行；请求结果不确定时先查询实际归属。
- 任务使用受保护的 properties 保存当前执行用户、稳定机器 ID 与名称、实际平台、worker/claim 标识、agent 类型、Herdr session/workspace/pane 及原生 agent session ID。尚未取得的会话信息与已取得信息区分，取得后补全。
- 用户以服务端认证身份为准。普通 properties 更新不能伪造或覆盖执行归属；执行更新保留 PR 等其他属性。
- 会话补全、执行更新、移交与完成均核验当前 claim，旧执行方不能覆盖新归属或完成新执行方的任务。

### W-05：调度与全局并发

- 有空闲名额时，配置仓库之间轮流获得领取机会，同一仓库内遵守服务端合格 ready 候选顺序。
- 空仓库或没有本平台合格候选的仓库不占名额；持续繁忙的仓库不能让其他仓库长期得不到领取机会。
- Task 从领取后准备执行到完整交付持续占一个名额，等待 CI/review、人工输入和恢复超限暂停期间均占用。降低上限不抢占已有任务。
- 同一仓库的不同 task 可由不同用户、机器或 worker 同时执行。

### W-06：稳定的 task worktree

- Worktree 由系统创建和销毁，每 task 一个。同一未完成 task 的继续、重试和恢复始终使用原 worktree、分支和成果。
- 退出、失败和崩溃保留未完成 worktree；资源缺失或身份不一致时保留现场并报告，不能新建空目录掩盖恢复失败。
- 完成交付后删除 worktree，保留执行历史和交付引用。清理只能作用于本 task 所拥有的资源。

### W-07：专用 Herdr 与 agent 执行

- Worker 自动启动和管理自己的专用 Herdr 实例，通过 Herdr API 启动、输入和观察 Copilot / Codex；不干扰人工或其他 worker 的实例。
- Herdr 与原生 agent 的会话关联可持久化，重启时核对并继续原执行，不要求人工重复输入已取得的标识。
- 启动和恢复前校验官方 Herdr/native agent 会话集成，以及恢复所需的原生历史是否可用；不满足时显示具体问题和修正方法并暂停该任务。Worker 不自动全局安装集成或修改全局 agent 配置。
- 开发 task 的 agent 负责实现、验证、提交、工作分支推送、PR、CI/review 反馈、合并和合并后验收，并遵守仓库权限、门禁与授权要求。其他允许 Agent 自动执行的 task 遵守其阶段和验收条件。
- Worker 使用 Herdr 最新状态观察运行、等待和结束，不需要公开 report 命令、结构化报告协议或结果文件。Herdr idle/done 或 agent 一轮结束不等于 task 完成。

### W-08：人工介入与显式移交

- 需要人工输入或授权时保留自动执行许可、平台、claim、worktree、原会话和并发名额，前台显示等待原因及原会话入口；人工通过 Herdr 处理后继续。
- 原执行用户或项目管理员可显式移交，并受项目访问权限约束。移交前须确认旧 agent 已停止，且原 worktree 成果和执行关联可继续使用。
- 无法确认停止、无法取得成果或执行平台不合格时保持暂停和原归属。跨机器移交必须先取得可继续的原成果，不能静默重新开始。
- 移交保持唯一有效 claim，使旧 claim 失去更新能力。

### W-09：SQLite、退出与恢复

- SQLite 保存当前执行状态与恢复所需检查点：worker 身份、仓库轮转位置、claim、冻结配置、worktree/分支、会话关联、最新状态、交付引用、失败原因、恢复次数、暂停与待清理事项。
- 影响外部资源的动作先保存恢复检查点。重启先核对 SQLite、服务端、Git 和 Herdr 的实际状态，再恢复任务和领取新任务；不确定的 claim、worktree、agent、PR、合并或清理结果不能按“未发生”直接重做。
- Worker 崩溃或机器失联不自动释放 claim，由原 worker 恢复或人工移交。worker 死亡不证明 agent 或工具已停止；无法确认原执行是否停止时暂停，避免重复 agent。
- Ctrl+C 停止新领取、当前 agent 与专用 Herdr，保存可恢复状态并保留未完成 claim/worktree。重启继续原任务。
- 异常退出或基础设施故障在原 worktree/会话上按配置上限恢复；计数、原因及暂停状态持久化，重启不清零。超限保留资源与名额，等待人工处理或明确恢复操作。

### W-10：完成核验与清理

- Agent 交付循环结束后，worker 独立核对当前 claim、task 与附件可读性、PR 仓库/提交/合并及必要检查、worktree 成果整合和验收证据引用，再通过服务端正常完成接口结束当前 claim。开发任务须具备 PR、检查/审查、合并及合并后验收证据。
- Agent 负责执行并记录任务验收；其验收文字是执行方声明，不是任意自然语言条件的独立证明。证据缺失、相互冲突或任务明确要求人工验收时保持 task 未完成，在原会话请求处理；不要求通用 Markdown 验收解析器或形式化证明。
- 完成后停止本 task 执行资源并删除 worktree，保留 SQLite 执行记录、PR/交付引用及 claim/session 标识。完成后修改自动执行许可或平台不能改写历史归属和实际平台。
- 删除失败记录具体错误和待清理状态，重启后只继续清理，不能重新执行已完成任务。清理不能影响其他任务或人工 Herdr。

### W-11：可观察性与交付验收

- 前台能够区分仓库、task、agent、平台、执行/等待/恢复/暂停/清理状态，显示实际错误与人工原会话入口。
- 自动执行许可和平台的 Web 交互遵循对应最终样式原型，保留双语、键盘、焦点和响应式规则，覆盖保存中、禁用、失败、版本冲突和不确定结果核对。
- 三平台运行、真实 Herdr/agent 行为、受控故障注入和生产端到端结果分别保留来源与验证边界；文档、模拟进程或正常退出不能替代真实会话恢复证明。

## 可观察验收

| 范围 | 必须观察到的结果 |
|---|---|
| W-01、W-07 | Linux/macOS/Windows 的安装入口可启动前台 worker；分别运行 Copilot/Codex；仓库缺失自动准备；原有仓库错误与配置错误可见；领取后的配置修改不影响原执行。 |
| W-02、W-03 | 验证旧任务迁移、新任务默认值、开关双向确认及取消/失败/未知结果、平台清除；覆盖自动执行许可、ready 与全部要求平台/worker 平台组合；不合格任务不会遮住后续合格候选或启动资源。 |
| W-04 | 多用户/机器/worker 竞争只出现一个有效 claim；覆盖查询后资格变化、旧版本、未知结果及旧 claim 更新；任务属性保留 PR 和实际会话关联。 |
| W-05 | 多仓库持续有任务时轮流获得机会；空与不兼容仓库被跳过；CI/review、人工等待及超限暂停均计入全局上限。 |
| W-06、W-08 | 继续和恢复使用原 worktree；人工进入原会话后继续；授权移交确认停止和成果连续性；越权、平台不合格或资源缺失保持拒绝或暂停。 |
| W-09 | Ctrl+C、强制结束 worker、Herdr 重启及机器重启后不产生第二个执行 agent；在外部动作结果落库前后注入中断，正确核对实际结果；恢复预算和暂停跨重启保持。 |
| W-10 | 已核验的开发任务合并并完成合并后验收，task 完成后删除 worktree且历史仍在；交付证据不足时不完成；清理失败跨重启只重试清理。 |
| W-11 | 前台和自动执行许可/平台 UI 展示与真实状态一致；错误、未知结果和人工处理入口可观察；各验收结果能关联到实际源代码、平台与运行环境。 |

完整 Goal 完成还要求必要实现 PR 经授权集成、实际门禁及端到端验收通过，并在对应 Daynight task 中保留交付引用。文档及 task breakdown 完成仅表示设计阶段交付。
