[架构设计](../design/daynight-auth.md)拥有实现机制，
[任务入口](../design/daynight-auth-tasks.md)连接 Daynight 中的执行资料。

## 目标与范围

多人使用同一服务时，通过项目成员关系控制访问。UniAuth 确认外部身份，Daynight
拥有本地用户、浏览器会话、个人访问令牌、项目成员和邀请。登录用户从 Web 或现有
CLI 创建私有项目，创建者自动成为管理员；Web 表单复用现有 project 创建 API。

覆盖现有 project、task、依赖图、属性和附件。成员使用已有业务读写能力，网页任务
字段编辑不由登录功能增加。已有项目归属后续手工处理，本交付只建立必要数据结构，
不自动补齐旧项目成员。所有未配置成员的项目按同一授权规则不可访问。

可信 HTML 保持现有同源执行，复用主站会话、普通 iframe、相对资源和键盘交互。
[附件架构决策](../../.agents/notes/implemented/architecture/2026-10-21-task-attachment-storage-design.md)
明确这是已采纳的约束，鉴权不能把独立预览域名、预览凭据或相关设施作为前提。

| 编号 | 必需行为 |
|---|---|
| AU1 | 使用现有 UniAuth 产品登录协议与 Go SDK，App Secret 仅保存在后端。 |
| AU2 | 稳定外部身份对应唯一的本地用户，邮箱/姓名/头像为可空资料，不用邮箱匹配身份。 |
| AU3 | 登录事务绑定发起浏览器，原子校验和消费后才领取一次性身份。重放、过期、错误绑定与领取失败明确拒绝。 |
| AU4 | Web 使用可注销/到期的主站会话；CLI/Agent 使用关联用户的可命名、到期、撤销的个人访问令牌，明文只展示一次。 |
| AU5 | 创建项目与添加创建者 admin 在同一事务提交。角色只有 admin/member，两者具有现有业务读写能力。 |
| AU6 | 只有 admin 能管理成员、角色和邀请；每个新项目至少保留一名 admin，并发操作也必须保持。 |
| AU7 | 项目列表先按成员筛选再分页；详情、任务、图、属性、附件列表、下载及预览逐请求执行项目授权。 |
| AU8 | 邀请有有效期、可撤销、单次使用；接受者先登录再明确确认，加入角色为 member。 |
| AU9 | 移除成员后拒绝新准入请求；已获授权并开始的文件传输允许完成。角色不固化在会话或令牌中。 |
| AU10 | 附件维持可信同源预览，以主站会话验证资源请求，保留脚本、模块、相对 CSS/图片/fetch、Esc/Tab 和焦点恢复。 |
| AU11 | 启用鉴权时，全部服务入口、客户端、部署健康检查和既有验收同次适配，不能依赖前端隐藏按钮。 |
| AU12 | 错误、取消及不确定写入可见；秘密不进入诊断、日志、仓库绑定或持久 URL。 |

## 身份与凭据

配置一个 UniAuth 服务和已注册 App，使用该 App 允许的 Microsoft/Google/GitHub
入口。完整 provider-qualified id 映射到本地 UUID，不同身份不按同邮箱自动合并。
资料更新不改变本地用户和成员关系。

浏览器使用服务端持久化的主站会话。生产 Cookie 为 host-only、Secure、HttpOnly、
SameSite=Lax；本机 loopback HTTP 使用明确的开发配置和适合 HTTP 的 Cookie 名称。
返回位置限主站内部路径。注销终止当前 Daynight 会话，上游登录状态由 UniAuth 管理。
Cookie 写请求校验精确主站 Origin；明确提供无效 Bearer 时拒绝，不回退到 Cookie。

PAT 由 Web 会话创建，只显示用户自己的元数据。撤销/到期后新请求返回未认证，不
影响其他会话或令牌。PAT 代表用户当前全部项目权限，不另设令牌角色。CLI 凭据绑定
配置的服务 origin，不进入仓库绑定、明文命令参数或日志；重定向不得转发凭据。

## 项目、成员与邀请

| 操作 | member | admin |
|---|---|---|
| 项目、任务、图、属性和成员名单读取 | 允许 | 允许 |
| 已有任务、依赖、属性写入和附件管理 | 允许 | 允许 |
| 邀请、移除成员、调整角色和撤销邀请 | 拒绝 | 允许 |

项目/任务 ID、仓库地址与本地绑定不是凭据。成员管理携带所观察到的成员版本，过期
修改返回 version_conflict；成员版本是独立于 task.version 的不连续正整数观察标识。
移除后重新加入获得新版本，旧观察仍冲突；无变化角色更新保留版本。最后一位 admin 不能删除或
降级。旧项目内容、版本、时间、路径和依赖不改变，后续手工添加成员即可使用。

邀请固定七天，属于项目，创建者离任不自动撤销。创建时一次显示可复制链接；列表
只显示元数据和撤销入口。有效期至消费、到期或管理员撤销。接受者必须登录并明确
确认，GET、链接预览、inspect 和登录跳转不消费。有效邀请只允许查看项目名称等最小
摘要。接受与消费原子提交，并发只增加一名新成员；已有成员不升级角色且不消费邀请。

## 同源附件

HTML 附件继续作为可信项目代码，拥有浏览者当前的主站权限。这沿用既有附件决策；
项目授权验证每个服务端资源请求，不提供上传代码的执行沙箱。

普通 iframe、图片、PDF、相对 CSS/JS/模块和 fetch 复用主站 Cookie。HEAD 和后续
GET 都执行鉴权。会话失效返回明确的 401，不将登录 HTML 当成文件；Web 使用已有
错误反馈引导重新登录。下载继续使用 attachment 语义，文件目录和内容不改写。
抽屉通过现有同源文档桥处理 Esc、Tab 和焦点，不增加预览会话或消息协议。

继续一次一个文件、bucket/path 和原预算。文件系统与 PG 非原子性保留 K1，普通
IO/数据库错误可见；不承诺撤回已发送字节或中止已准入的文件操作。

## 错误与运行边界

| 场景 | 对外结果 |
|---|---|
| 缺失、无效、撤销或到期凭据 | 401 unauthenticated JSON |
| 项目不存在或不是成员 | 404 not_found JSON |
| member 调用 admin 功能、Cookie 写请求来源错误 | 403 forbidden JSON |
| 观察版本过期、最后 admin 条件不满足 | 409 version_conflict / last_admin |
| 邀请已消费、到期或撤销 | 410 invitation_unavailable |

数据 API 不跳转登录 HTML。登录和 callback 是浏览器导航入口；已验证并消费的
callback 失败会返回主站的通用登录错误状态，错误绑定仍明确拒绝。Web 自己处理登录
状态，CLI 提示配置令牌；失败不能伪装成空
项目或空成员。生产继续一个应用 origin，经现有入口提供 HTTPS；Go 保持 loopback。
健康检查使用无业务数据的独立入口，不匿名读取项目列表。启用后缺少必需鉴权配置
拒绝启动，所有业务入口强制认证。

开发/CI 复用数值 loopback 的同源 HTTP 与现有进程/容器结构，显式启用 SDK 已支持的
AllowLoopbackHTTP。固定 public origin 与 listener 分开配置，注册精确 callback；
不增加域名、证书或网关。真实 UniAuth 能力不足时记录具体协议缺口与证据，交由
UniAuth 维护者处理，不推导额外架构。
