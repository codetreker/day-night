# 任务依赖追踪与详情阅读

状态：UX-T1 完整上下文与 UX-T3 居中详情已交付。UX-T2 分两个 focused PR：当前先交付渐进概览（TI1–TI2 的可见规则），后续 [#121](https://github.com/codetreker/daynight/pull/121) 交付依赖选择、独立详情和曲线（TI3–TI5）；两者均合并才完成任务。UX-T4 Markdown 待实现。本文包含最终目标要求；当前卡片主体仍打开 TaskDetailDialog，连线仍为既有折线。[设计](../design/daynight-task-inspection.md)、[拆分](../design/daynight-task-inspection-tasks.md)和[目标交互原型](../design/mockups/task-inspection/index.html)分别拥有机制、交付边界和最终视觉，原型不表示后续交互已经上线。

## 目的与适用范围

在任务图中直接查看一个任务依赖哪些前置任务，再通过独立入口阅读完整内容。图内卡片承担依赖追踪，详情使用居中浮层。任务的 `description` 作为 Markdown 展示，公开 `using-daynight` skill 同步描述写法和实际附件链接。

图内卡片的选择规则适用于任务依赖画布。独立任务列表点击条目直接打开同一详情浮层；独立任务与任务链的标签分类、过滤、计数和浏览偏好由其原任务负责。

## 必须交付的行为

| 编号 | 要求 |
|---|---|
| TI1 | 完整链投影 P 保留根、全部可达后续及它们的所有祖先，外部前置无关后续不加入 P；链内进度/状态和项目统计仍按完整数据。P 不超过 50 个任务且 100 条依赖时全显；其余从根按稳定快照顺序做后续优先、前置其次的无向 BFS，仅接纳加入后实际诱导图仍满足 50/100 的候选，只遍历接纳任务。链内与外部使用同一渐进规则。 |
| TI2 | 每卡片提供前置/后续方向控件，一次加入 P 内该方向前 20 个隐藏直接邻居，不递归，准确显示新增任务、诱导边及剩余数；手动展开无边数上限，可超过初始阈值。S 内两端均可见的全部真实依赖必须显示，无聚合卡片或捷径。两方向都无可展开邻居时不显示 footer 或分隔线，卡片为 220×96；至少一方向有控件时保留 40px 双列 footer，卡片为 220×136，空方向保留列位置。布局、边端点、视口适配、锚点居中和键盘揭示使用实际尺寸。工具栏区分完整/可见数量；外部任务、四状态、阻塞与共享标识保留。“收起到概览”重算并定位概览。当前主体继续打开已有详情，方向控件是兄弟原生按钮。 |
| TI3 | 点击图内卡片主体选中该任务，同时高亮它的全部传递上游及相关依赖连线。选中任务与上游前置有不同的可见样式；无关节点和连线适度淡化，文本及状态仍可辨认。点击另一张卡片替换选择；再次点击当前卡片或点击画布空白处清除选择。根任务无前置时，仅标记自身。 |
| TI4 | 依赖连线使用平滑转弯，保留前置到后续的箭头方向、布局路由和外部依赖的虚线语义。高亮同时作用于整条连线及箭头，外部虚线高亮后仍为虚线。选择仅改变样式；节点位置、连线路径、缩放和平移保持稳定。 |
| TI5 | 每张图内卡片提供独立的“详情”入口。主体和详情入口是两个可通过键盘操作的原生控件，不嵌套交互元素。Enter/空格作用于当前聚焦控件：主体切换依赖高亮，详情入口打开详情。打开详情不改变已有依赖选择；关系引用只切换详情内容。 |
| TI6 | 详情在浏览器可用视口居中显示，桌面最大宽度 960px、四周至少留 24px；窄屏四周至少留 12px。窗口最大高度为可用视口减去两倍边距，标题栏、详情页签和关闭入口保持可用。默认概览保留描述、PR、状态、关系及元数据并独立滚动；附件页签使用所有宽度下的左右分屏，右侧仅有一个纵向滚动所有者，行为以附件要求为准。320px 宽度下页面无整体横向溢出，表格和代码块在局部滚动。 |
| TI7 | 详情保留背景不可交互、焦点进入和约束、关闭按钮、遮罩关闭、Esc 关闭以及焦点恢复。全屏图内可打开居中详情；Esc 先关闭详情，再退出全屏。详情关闭后恢复到打开它的详情入口或独立任务条目；入口已消失时沿用全屏退出按钮、当前根条目、项目标题的可用回退。图刷新和卸载不遗留滚动锁或 inert 状态。该模态约束不扩展到独立附件阅读页，其普通浏览器键盘行为由附件要求拥有。 |
| TI8 | `description` 按 CommonMark 与 GFM 展示，包括标题、段落、列表、引用、表格、代码块及链接。原始 HTML 作为文本展示，URL 协议处理沿用现有 Markdown 规则。空描述显示“暂无描述”；读取错误保留局部重试。API 仍保存原始字符串，CLI 和 Agent 读取原始 Markdown。 |
| TI9 | 描述中的相对附件链接及图片以当前任务附件根目录为基准；Markdown 附件内部链接仍以该文件所在目录为基准。普通左键点击不带 query/hash 的相对附件链接，激活当前详情的附件页签，使用现有附件控制器选中文件并将预览带入焦点。链接保留真实 preview URL，修饰键、非主键和上下文菜单保留浏览器行为。带 query/hash 的链接按真实 URL 导航，不承诺新增 Markdown 标题锚点功能。 |
| TI10 | 相对链接不能越过当前任务附件根。附件清单尚未完整读取时保留加载或错误状态；只有完整清单才能判定引用不存在。无效路径、文件缺失或预览失败提供可见说明及适用的重试入口。描述导航与附件区域共用同一个附件状态所有者，不发起相互独立的重复清单读取。 |
| TI11 | npm 中的 `using-daynight` skill 要求普通任务与 Goal 阶段均用 Markdown 写自足简介，说明具体问题、行动、范围、交付物、约束、简明可观察完成条件和真实资料引用；详细方案、完整验收与证据归任务专属主 Markdown 附件。共享 Goal 和设计引用实际来源 task ID 与附件路径，或已核验的不可变仓库 URL，不向每个任务复制整套资料。依赖只写入 `dependsOn`，PR 写入 `properties.pullRequests`。资料要求按阶段判断，Goal 澄清产出适用原型，架构实际登记后继；创建后确认上传或来源可读再加入引用，执行与更新保留完整 Markdown 和有效引用。 |

## 生命周期与刷新

当前渐进图保存实际 S，项目/根/页签变化或卸载后清除。方向展开重新布局、在当前缩放居中操作卡片并聚焦主体；重置重新计算概览并 framing，保留重置控件焦点。成功刷新保留实际 S 中仍属于新 P 的 ID，加根后仅保留诱导无向图的根连通分量，不自动补入新基线或新任务；刷新保留视口，失败保留旧数据、S 和视口。重置/remount 才计算新概览。

当前主体仍按既有回调打开 TaskDetailDialog，详情关系切换只改变详情资源。详情打开时刷新不抢焦点，入口消失后沿用关闭时回退；概览/附件页签、分屏预览、单一附件控制器、滚动和语言状态保持既有生命周期。语言变化重译方向控件和计数，不改变 S 或增加业务请求。

后续依赖追踪 PR 的目标：依赖选择独立于详情资源和可见 S，不持久化；成功刷新从完整数据重算仍可见的选择，隐藏则清除，失败保持。H 由完整数据计算，可见成员高亮且隐藏祖先按 ID 去重计数；选择、详情打开/关闭和关系导航不展开、不布局、不移动视口。该行为与 TI3–TI5 一同验收，当前概览 PR 不声明其已实现。

## 验收与规模

当前概览 PR 独立验证 50/100 临界、稳定后续优先 BFS、只遍历接纳节点、实际诱导边预算、小链位于大项目、双向 20 项直接邻居、共享去重、无关外部后续排除、proposed/完成状态及无手动边上限。浏览器验证准确批次计数、展开锚点、重置 framing/focus、实际集合刷新连通修剪、失败保留和打开详情时不抢焦点。

API 上限仍为完整项目 1,000 任务/5,000 依赖。四个容量输入保持完整任务及原有 999/5,000 边，每图五次；浏览器改验有界概览、全部可见诱导边与显式展开/重置，不要求所有输入同时进入 DOM。`openMs ≤ 3000`，原有详情/缩放/平移 ≤300ms，保留详情→关闭→立即缩放/平移序列，不插入重置、适应或等待。31 项场景、零重试、timeout、真实运行目标、覆盖率、超限拒绝与资源清理保持。当前使用既有折线/虚线独立判断，不声明 selectMs、隐藏 H 或曲线容量结论。

后续 #121 对 TI3–TI5 验证完整 H/隐藏祖先、高亮同步、兄弟选择/详情控件、选择前后几何/视口稳定及独立曲线/paint/marker 判断，并增加对应选择反馈测量。Markdown 和 skill 继续由 UX-T4 验收。目标原型只证明原型行为；每个 PR 都必须提供自身真实源码绑定证据，两者均交付才将 UX-T2 完成。
