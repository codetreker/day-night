状态：UX-T1、UX-T3 与 [PR #134](https://github.com/codetreker/daynight/pull/134) 的渐进概览已交付。依赖检查从当前主线重新实现，替代 PR 尚待创建；旧 [#121](https://github.com/codetreker/daynight/pull/121) 已关闭弃用，不是完成前置，其验证仅作历史记录。UX-T2 在替代实现通过当前源码验收并合并后完成；UX-T4 Markdown 待实现。本文拥有确认后的最终行为，[设计](../design/daynight-task-inspection.md)、[拆分](../design/daynight-task-inspection-tasks.md)和[原型](../design/mockups/task-inspection/index.html)分别拥有机制、交付边界和目标视觉。替代代码已按下列交互实现，当前源码运行与交付证据待完成。

## 目的与适用范围

在任务图中直接查看一个任务依赖哪些前置任务，再通过独立入口阅读完整内容。图内卡片承担依赖追踪，详情使用居中浮层。任务的 `description` 作为 Markdown 展示，公开 `using-daynight` skill 同步描述写法和实际附件链接。

图内卡片的选择规则适用于任务依赖画布。独立任务列表点击条目直接打开同一详情浮层；独立任务与任务链的标签分类、过滤、计数和浏览偏好由其原任务负责。

## 必须交付的行为

| 编号 | 要求 |
|---|---|
| TI1 | 完整链投影 P 保留根、全部可达后续及它们的所有祖先，外部前置无关后续不加入 P；链内进度/状态和项目统计仍按完整数据。P 不超过 50 个任务且 100 条依赖时全显；其余从根按稳定快照顺序做后续优先、前置其次的无向 BFS，仅接纳加入后实际诱导图仍满足 50/100 的候选，只遍历接纳任务。链内与外部使用同一渐进规则。 |
| TI2 | 每卡片提供前置/后续方向控件，一次加入 P 内该方向前 20 个隐藏直接邻居，不递归，准确显示新增任务、诱导边及剩余数；手动展开无边数上限，可超过初始阈值。S 内两端均可见的全部真实依赖必须显示，无聚合卡片或捷径。工具栏区分完整/可见数量；外部任务、四状态、阻塞与共享标识保留。“收起到概览”重算并定位概览。当前主体继续打开已有详情，方向控件是兄弟原生按钮。 |
| TI3 | 主体选择任务，从完整数据计算其全部上游H；只高亮当前可见祖先和它们的全部真实可见连线/箭头，按任务ID去重显示隐藏上游数。选中与前置样式不同，无关项淡化但文字/状态可辨。同卡片或画布空白清除，其他卡片替换；高亮不自动展开、不布局、不重算几何或改变视口，根无前置时仅选中自身。 |
| TI4 | 全部可见依赖平滑转弯，保留前置到后续方向、节点避让及外部5/4虚线语义。源右中心到目标左中心，经统一列间水平/垂直通道连接，16单位净空与≤12单位Q圆角保证平滑避让。实际body、dash pieces及原生箭头同步高亮；高亮前后S、节点位置、canonical路线、pieces和平移/缩放不变。 |
| TI5 | 主体、独立Details与方向控件均为无嵌套的兄弟原生控件。Details以链接视觉打开现有居中TaskDetailDialog；Enter/空格执行当前控件动作。Details开关与关系导航不改S或图选择，方向展开和全局reset沿用PR134的显式结构/焦点行为。 |
| TI6 | 详情在浏览器可用视口居中显示，桌面最大宽度 960px、四周至少留 24px；窄屏四周至少留 12px。窗口最大高度为可用视口减去两倍边距，标题栏、详情页签和关闭入口保持可用。默认概览保留描述、PR、状态、关系及元数据并独立滚动；附件页签使用所有宽度下的左右分屏，右侧仅有一个纵向滚动所有者，行为以附件要求为准。320px 宽度下页面无整体横向溢出，表格和代码块在局部滚动。 |
| TI7 | 详情保留背景不可交互、焦点进入和约束、关闭按钮、遮罩关闭、Esc 关闭以及焦点恢复。全屏图内可打开居中详情；Esc 先关闭详情，再退出全屏。详情关闭后恢复到打开它的详情入口或独立任务条目；入口已消失时沿用全屏退出按钮、当前根条目、项目标题的可用回退。图刷新和卸载不遗留滚动锁或 inert 状态。该模态约束不扩展到独立附件阅读页，其普通浏览器键盘行为由附件要求拥有。 |
| TI8 | `description` 按 CommonMark 与 GFM 展示，包括标题、段落、列表、引用、表格、代码块及链接。原始 HTML 作为文本展示，URL 协议处理沿用现有 Markdown 规则。空描述显示“暂无描述”；读取错误保留局部重试。API 仍保存原始字符串，CLI 和 Agent 读取原始 Markdown。 |
| TI9 | 描述中的相对附件链接及图片以当前任务附件根目录为基准；Markdown 附件内部链接仍以该文件所在目录为基准。普通左键点击不带 query/hash 的相对附件链接，激活当前详情的附件页签，使用现有附件控制器选中文件并将预览带入焦点。链接保留真实 preview URL，修饰键、非主键和上下文菜单保留浏览器行为。带 query/hash 的链接按真实 URL 导航，不承诺新增 Markdown 标题锚点功能。 |
| TI10 | 相对链接不能越过当前任务附件根。附件清单尚未完整读取时保留加载或错误状态；只有完整清单才能判定引用不存在。无效路径、文件缺失或预览失败提供可见说明及适用的重试入口。描述导航与附件区域共用同一个附件状态所有者，不发起相互独立的重复清单读取。 |
| TI11 | npm发布的using-daynight skill指导用Markdown写自足任务描述，包含具体行动、范围、交付物、约束、简明可观察完成条件及真实引用；专属主Markdown保留Solution/Acceptance criteria与完整证据。共享要求/设计/原型按当前所有权引用，不恢复problem-only或强制复制整包规则。dependsOn与PR属性语义保持，上传确认后才加实际链接，更新保留完整Markdown和有效引用。 |

## 生命周期与刷新

当前渐进图保存实际 S，项目/根/页签变化或卸载后清除。方向展开重新布局、在当前缩放居中操作卡片并聚焦主体；重置重新计算概览并 framing，保留重置控件焦点。成功刷新保留实际 S 中仍属于新 P 的 ID，加根后仅保留诱导无向图的根连通分量，不自动补入新基线或新任务；刷新保留视口，失败保留旧数据、S 和视口。重置/remount 才计算新概览。

当前主体仍按既有回调打开 TaskDetailDialog，详情关系切换只改变详情资源。详情打开时刷新不抢焦点，入口消失后沿用关闭时回退；概览/附件页签、分屏预览、单一附件控制器、滚动和语言状态保持既有生命周期。语言变化重译方向控件和计数，不改变 S 或增加业务请求。

后续依赖追踪 PR 的目标：依赖选择独立于详情资源和可见 S，不持久化；成功刷新从完整数据重算仍可见的选择，隐藏则清除，失败保持。H 由完整数据计算，可见成员高亮且隐藏祖先按 ID 去重计数；选择、详情打开/关闭和关系导航不展开、不布局、不移动视口。该行为与 TI3–TI5 一同验收，替代检查实现需独立证明该行为；当前生产尚未提供它。

## 验收与规模

已交付PR134独立验证过 50/100 临界、稳定后续优先 BFS、只遍历接纳节点、实际诱导边预算、小链位于大项目、双向 20 项直接邻居、共享去重、无关外部后续排除、proposed/完成状态及无手动边上限。浏览器验证准确批次计数、展开锚点、重置 framing/focus、实际集合刷新连通修剪、失败保留和打开详情时不抢焦点。

API 上限仍为完整项目 1,000 任务/5,000 依赖。四个容量输入保持完整任务及原有 999/5,000 边，每图五次；浏览器改验有界概览、全部可见诱导边与显式展开/重置，不要求所有输入同时进入 DOM。`openMs ≤ 3000`，原有详情/缩放/平移 ≤300ms，保留详情→关闭→立即缩放/平移序列，不插入重置、适应或等待。31 项场景、零重试、timeout、真实运行目标、覆盖率、超限拒绝与资源清理保持。当前使用既有折线/虚线独立判断，不声明 selectMs、隐藏 H 或曲线容量结论。
