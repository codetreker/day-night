# 任务依赖追踪与详情阅读

状态：完整上游上下文（UX-T1，对应 TI1–TI2）已实现；依赖选择与平滑连线、居中详情和 Markdown 描述（UX-T2–UX-T4）待实现。本文拥有任务卡片选择、完整上游展示、平滑依赖连线、居中详情和 Markdown 描述的目标行为。[设计](../design/daynight-task-inspection.md)说明机制，[任务拆分](../design/daynight-task-inspection-tasks.md)定义交付边界，[交互原型](../design/mockups/task-inspection/index.html)展示最终视觉与主要交互。已实现上下文与现有详情行为由[看板基线](daynight-web.md)和[附件要求](daynight-task-attachments.md)描述。

## 目的与适用范围

在任务图中直接查看一个任务依赖哪些前置任务，再通过独立入口阅读完整内容。图内卡片承担依赖追踪，详情使用居中浮层。任务的 `description` 作为 Markdown 展示，公开 `using-daynight` skill 同步描述写法和实际附件链接。

图内卡片的选择规则适用于任务依赖画布。独立任务列表若已交付，仍可点击条目直接打开同一详情浮层；独立任务与任务链的标签分类、过滤、计数和浏览偏好由其原任务负责。

## 必须交付的行为

| 编号 | 要求 |
|---|---|
| TI1 | 展开任务链时，一次展示根及全部可达后续任务，并递归补齐这些任务的全部上游前置。补入的外部前置只提供上下文，不引入其无关后续。任务链进度与聚合状态继续仅计算链内去重任务，项目统计不重复计数。 |
| TI2 | 图例和节点明确区分链内任务与外部前置，标记“外部前置”并说明已补齐全部上游。工具栏分别显示链内任务、外部前置和依赖数量。保持已完成前置可见，保留任务自身状态、阻塞和共享标识。 |
| TI3 | 点击图内卡片主体选中该任务，同时高亮它的全部传递上游及相关依赖连线。选中任务与上游前置有不同的可见样式；无关节点和连线适度淡化，文本及状态仍可辨认。点击另一张卡片替换选择；再次点击当前卡片或点击画布空白处清除选择。根任务无前置时，仅标记自身。 |
| TI4 | 依赖连线使用平滑转弯，保留前置到后续的箭头方向、布局路由和外部依赖的虚线语义。高亮同时作用于整条连线及箭头，外部虚线高亮后仍为虚线。选择仅改变样式；节点位置、连线路径、缩放和平移保持稳定。 |
| TI5 | 每张图内卡片提供独立的“详情”入口。主体和详情入口是两个可通过键盘操作的原生控件，不嵌套交互元素。Enter/空格作用于当前聚焦控件：主体切换依赖高亮，详情入口打开详情。打开详情不改变已有依赖选择；关系引用只切换详情内容。 |
| TI6 | 详情在浏览器可用视口居中显示，桌面最大宽度 960px、四周至少留 24px；窄屏四周至少留 12px。窗口最大高度为可用视口减去两倍边距，内容区独立滚动，标题栏和关闭入口保持可用。描述、PR、附件、状态、关系及元数据保持完整。320px 宽度下页面无整体横向溢出，表格和代码块在局部滚动。 |
| TI7 | 详情保留背景不可交互、焦点进入和约束、关闭按钮、遮罩关闭、Esc 关闭以及焦点恢复。全屏图内可打开居中详情；Esc 先关闭详情，再退出全屏。详情关闭后恢复到打开它的详情入口或独立任务条目；入口已消失时沿用全屏退出按钮、当前根条目、项目标题的可用回退。图刷新和卸载不遗留滚动锁或 inert 状态。 |
| TI8 | `description` 按 CommonMark 与 GFM 展示，包括标题、段落、列表、引用、表格、代码块及链接。原始 HTML 作为文本展示，URL 协议处理沿用现有 Markdown 规则。空描述显示“暂无描述”；读取错误保留局部重试。API 仍保存原始字符串，CLI 和 Agent 读取原始 Markdown。 |
| TI9 | 描述中的相对附件链接及图片以当前任务附件根目录为基准；Markdown 附件内部链接仍以该文件所在目录为基准。普通左键点击不带 query/hash 的相对附件链接，在当前详情的附件区域预览文件并将该区域带入视野和焦点。链接保留真实 preview URL，修饰键、非主键和上下文菜单保留浏览器行为。带 query/hash 的链接按真实 URL 导航，不承诺新增 Markdown 标题锚点功能。 |
| TI10 | 相对链接不能越过当前任务附件根。附件清单尚未完整读取时保留加载或错误状态；只有完整清单才能判定引用不存在。无效路径、文件缺失或预览失败提供可见说明及适用的重试入口。描述导航与附件区域共用同一个附件状态所有者，不发起相互独立的重复清单读取。 |
| TI11 | npm 中的 `using-daynight` skill 要求任务描述使用 Markdown 表达问题与真实附件链接；方案和验收继续归一个主 Markdown 附件，依赖仍只写入 `dependsOn`，PR 仍写入 `properties.pullRequests`。创建后确认上传成功再加入真实引用；执行与更新任务时保留完整 Markdown 和仍有效的引用。 |

## 生命周期与刷新

依赖选择属于当前挂载画布，不持久化。切换项目、任务链、标签或卸载画布时清除。成功刷新后，所选任务仍在当前投影中则从新快照重新计算高亮；已消失则清除并保留可用焦点。刷新失败继续显示上次成功快照及其高亮，并显示原有失败提示。

详情选择与依赖选择相互独立。详情打开后仍可通过关系切换任务，快照变化继续使用既有不一致提示、取消和响应身份校验；详情中的最新数据不局部改写图。打开与关闭详情不清除依赖高亮，不重新布局，也不重置图视口。原有任务链展开、完成链过滤和项目隔离的偏好继续生效。

## 验收与规模

模型验收覆盖链、菱形、多根共享后续、递归外部前置、外部前置的无关分支、已完成前置及独立任务。图中应出现全部需要的前置与依赖，链内数量和状态保持正确。

浏览器验收同时检查曲线几何、箭头、虚线连续性、节点避让、完整覆盖、连线同步高亮、两个卡片控件、居中尺寸、全屏分层 Esc、焦点恢复、Markdown 内容及附件链接。鼠标和键盘路径都必须验证，覆盖桌面与 320px 窄屏，以及加载、空态、失败和刷新后任务消失。

保留现有完整项目上限 1,000 个任务和 5,000 条依赖。既有生产容量矩阵、五次展开及最慢不超过 3,000ms 的门槛继续有效；布局后的选择、详情本地反馈、缩放和平移不超过 300ms。新增跨链祖先密集场景和高亮选择测量，不能以删边、隐藏前置、改变容量场景或提高预算换取通过。设计原型验证只证明原型交互；生产性能由实现任务提供真实生产构建证据。
