# 任务依赖追踪与详情阅读

状态：UX-T1 的完整依赖数据已交付；UX-T2 采用渐进图概览、完整依赖追踪、平滑高亮连线和独立详情入口，运行与交付证据待完成。UX-T3 居中详情已由 [PR #124](https://github.com/codetreker/daynight/pull/124) 交付；UX-T4 Markdown 描述待实现。本文拥有任务卡片选择、渐进任务图、完整上游追踪和平滑依赖连线、居中详情和 Markdown 描述的目标行为。[设计](../design/daynight-task-inspection.md)说明机制，[任务拆分](../design/daynight-task-inspection-tasks.md)定义交付边界，[交互原型](../design/mockups/task-inspection/index.html)展示最终视觉与主要交互。已实现上下文与居中详情行为由[看板基线](daynight-web.md)和[附件要求](daynight-task-attachments.md)描述。

## 目的与适用范围

在任务图中直接查看一个任务依赖哪些前置任务，再通过独立入口阅读完整内容。图内卡片承担依赖追踪，详情使用居中浮层。任务的 `description` 作为 Markdown 展示，公开 `using-daynight` skill 同步描述写法和实际附件链接。

图内卡片的选择规则适用于任务依赖画布。独立任务列表点击条目直接打开同一详情浮层；独立任务与任务链的标签分类、过滤、计数和浏览偏好由其原任务负责。

## 必须交付的行为

| 编号 | 要求 |
|---|---|
| TI1 | 打开任务链时，数据投影 P 仍包含根及全部可达后续和这些任务的全部祖先；外部前置的无关后续不加入 P。链内与外部任务共用渐进可见集合 S：P 不超过 50 个任务且 100 条依赖时全部展示；否则从根进行稳定、后续优先的无向 BFS，只接纳使实际诱导图仍不超过 50 个任务/100 条依赖的候选，仅从已接纳任务继续遍历。链进度、聚合状态和项目统计仍按完整数据计算。 |
| TI2 | 可见卡片标记“外部前置”、状态、阻塞和共享信息。每张卡片提供显式前置/后续展开，一次加入 P 内该方向最多 20 个隐藏直接邻居，按快照顺序，显示本批准确新增任务和真实依赖数；手动展开没有新增边数上限，可超过初始概览限制。绘制 S 内两端均可见的全部真实依赖，不生成捷径、聚合节点或虚构连线。工具栏区分可见与完整投影数量；“收起到概览”重新计算概览并定位视口。已完成任务遵循同一拓扑规则。 |
| TI3 | 点击卡片主体选择该任务，完整祖先集合 H 从完整数据计算。可见的所选任务、全部可见祖先及真实连接线同步高亮；显示按任务 ID 去重的隐藏祖先数。选中与前置样式不同，无关项适度淡化且文字和状态可辨。再次点击同一卡片或空白清除，点击其他卡片替换；选择不自动展开、不重新布局、不改变视口。根任务无前置时仅标识自身。 |
| TI4 | 可见依赖线使用平滑转弯，保留前置到后续的方向及外部虚线语义。路线从前置右侧中心到后续左侧中心，经无障碍 rank 通道避让可见卡片。高亮同时作用于完整可见线及箭头，外部线仍为虚线；选择前后节点位置、标准路径、缩放和平移不变，显式展开/重置可以改变可见结构、布局及视口，成功刷新只协调保留集合与布局并保持视口。 |
| TI5 | 卡片主体、“详情”和方向展开均为可键盘操作的兄弟原生控件，无嵌套。Enter/空格执行当前控件动作；详情打开及关系导航不改变依赖选择或可见集合。方向展开允许重新布局，并在当前缩放保持操作卡片可访问；全局重置重新定位概览。 |
| TI6 | 详情在浏览器可用视口居中显示，桌面最大宽度 960px、四周至少留 24px；窄屏四周至少留 12px。窗口最大高度为可用视口减去两倍边距，内容区独立滚动，标题栏和关闭入口保持可用。描述、PR、附件、状态、关系及元数据保持完整。320px 宽度下页面无整体横向溢出，表格和代码块在局部滚动。 |
| TI7 | 详情保留背景不可交互、焦点进入和约束、关闭按钮、遮罩关闭、Esc 关闭以及焦点恢复。全屏图内可打开居中详情；Esc 先关闭详情，再退出全屏。详情关闭后恢复到打开它的详情入口或独立任务条目；入口已消失时沿用全屏退出按钮、当前根条目、项目标题的可用回退。图刷新和卸载不遗留滚动锁或 inert 状态。 |
| TI8 | `description` 按 CommonMark 与 GFM 展示，包括标题、段落、列表、引用、表格、代码块及链接。原始 HTML 作为文本展示，URL 协议处理沿用现有 Markdown 规则。空描述显示“暂无描述”；读取错误保留局部重试。API 仍保存原始字符串，CLI 和 Agent 读取原始 Markdown。 |
| TI9 | 描述中的相对附件链接及图片以当前任务附件根目录为基准；Markdown 附件内部链接仍以该文件所在目录为基准。普通左键点击不带 query/hash 的相对附件链接，在当前详情的附件区域预览文件并将该区域带入视野和焦点。链接保留真实 preview URL，修饰键、非主键和上下文菜单保留浏览器行为。带 query/hash 的链接按真实 URL 导航，不承诺新增 Markdown 标题锚点功能。 |
| TI10 | 相对链接不能越过当前任务附件根。附件清单尚未完整读取时保留加载或错误状态；只有完整清单才能判定引用不存在。无效路径、文件缺失或预览失败提供可见说明及适用的重试入口。描述导航与附件区域共用同一个附件状态所有者，不发起相互独立的重复清单读取。 |
| TI11 | npm 中的 `using-daynight` skill 要求任务描述使用 Markdown 表达问题与真实附件链接；方案和验收继续归一个主 Markdown 附件，依赖仍只写入 `dependsOn`，PR 仍写入 `properties.pullRequests`。创建后确认上传成功再加入真实引用；执行与更新任务时保留完整 Markdown 和仍有效的引用。 |

所有新增控件、批次/隐藏数量、通知和可访问说明接入既有英语/简体中文目录；语言切换保留 S、依赖选择、视口及详情资源，不增加业务请求或改变布局输入。语言契约由[双语需求](daynight-web-i18n.md)拥有。

## 生命周期与刷新

当前挂载画布拥有 S 与依赖选择，均不持久化；项目、根、页签变化或卸载后清除，新挂载重新计算概览。全局重置重新计算初始集合并定位视口，焦点保留在稳定的重置控件；选中任务仍可见则保留，否则清除。

成功刷新时保留实际可见 ID 中仍属于新 P 的任务，加上根后仅保留诱导无向图的根连通分量；不自动合入新概览或新到任务。重置或重新挂载才计算新基线。仍可见的选择按新完整数据重算 H，不可见则清除；刷新保持当前视口，失败保留旧快照、S、选择和视口。详情打开期间不能把焦点抢回图；详情入口消失后在关闭时使用既有回退。

详情和依赖选择相互独立。关系导航只切换详情资源，最新详情不局部改写项目图。打开/关闭详情不改变 S、高亮、布局或视口，保留既有取消、资源身份检查、差异提示和局部重试。项目展开、完成筛选及浏览偏好继续有效。

## 验收与规模

独立模型验收覆盖 50/100 边界、稳定后续优先 BFS、只遍历接纳节点、诱导边预算、小链位于大项目、两种方向的 20 个直接邻居批次、共享去重、外部无关后续排除、已完成任务、无手动边数上限、全局重置和实际可见集合的根连通刷新。每次展开的新增任务/依赖数及选择的隐藏祖先数都与完整数据独立复算。

浏览器覆盖显式展开/重置、可见图全部真实边、可见卡片和线/箭头同步高亮、隐藏祖先不触发可见变化、选择前后几何与视口稳定、详情及分层 Esc、焦点、失败刷新和打开详情时刷新。桌面与 320px 路径均验证鼠标和键盘。曲线与实际 body/marker 使用独立几何判断，保留后续居中详情和 Markdown 各自的验收。

API 的完整项目上限仍为 1,000 个任务和 5,000 条依赖。四个固定容量输入的完整任务/边集合不变，每图五次，打开可操作概览最慢不超过 3,000ms，选择、详情、缩放和平移反馈不超过 300ms。容量验收改为断言有界概览、完整可见诱导边、显式展开/重置及准确隐藏上游数，不要求 1,000/5,000 全部同时进入 DOM。每个样本保留普通态详情→关闭→立即缩放/平移，再测量当前可见任务的可信选择并在高亮态重复该序列；详情、缩放、平移各取两态较慢值，网络时间独立保留较大值。关闭到缩放之间不重置、不适应画布、不增加等待。生产构建与真实服务结果仍是交付门槛，原型不证明性能。
