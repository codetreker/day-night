## 目标与使用环境

通过本机浏览器查看 `daynight-server` 中的项目、任务进度和执行依赖。完整路径为：项目列表 → 项目详情 → 独立任务列表或任务链 → 查看任务详情。

沿用[服务端要求](daynight-server.md)的 project、task 和依赖语义。“根任务”是没有前置依赖的 task；“后续任务”是沿执行方向可达的 task，不引入父子任务模型。独立任务在完整图中既没有前置也没有后续；任务链页签沿用根任务投影，只包含有后续的根。分类取决于依赖关系，已完成前置不会让后续变成独立任务。页面展示已有数据；项目与任务的创建、修改继续使用现有 API。

## 必须交付的行为

| 编号 | 要求 |
|---|---|
| W1 | `/` 列出项目名称、仓库地址和创建时间。使用已有游标分页，提供“加载更多”；所有项目都可访问。未加载的项目不得算入全局统计，页面不展示假定完整的项目总数。 |
| W2 | 点击项目进入 `/projects/{projectId}`；直接打开或刷新此地址得到同一项目页面，并能返回项目列表。 |
| W3 | 项目顶部显示任务总数、已完成、待处理、进行中、可开始和被阻塞数量，以及完成比例。所有数字来自一个完整项目快照，按任务 ID 去重。 |
| W4 | 项目详情内提供“独立任务”和“任务链”两个页签，保留同一项目 URL、标题和完整项目统计。首次访问默认打开任务链，之后按项目恢复上次选择。页签数量分别表示完整快照中的独立任务数和非独立根任务链数，不受完成筛选影响；共享后续不合并根链。独立任务使用紧凑列表，显示标题、自身状态和创建时间，整行直接打开详情。任务链条目显示根标题、整链状态和完成进度：根及全部可达后续按 ID 去重，全部完成才为“已完成”；已有完成或进行中的任务且整链未结束为“进行中”；全部待处理为“待处理”。外部前置不计入整链状态，图节点和详情仍显示任务自身状态。两类各自默认隐藏已完成项，分别提供带完成数量的“显示已完成”复选框、可见/全部条目数和按项目保留的独立选择。两类均按创建时间倒序、相同时间 ID 倒序展示，保留服务端时间精度；更新时间不影响位置。紧凑条目的长标题自然换行并增高，整行原生按钮保留键盘操作。切换页签分别保留浏览位置及任务链展开选择，不增加 API 请求，不改变完整统计或图上下文。 |
| W5 | 在任务链页签点击条目展开横向有向图；同时最多展开一个条目。当前展开根或明确的全部折叠按项目保存在当前站点的浏览器本地存储，整页刷新及离开后返回仍保留。首次访问任务链页签时展开当前排序的首个可见非独立根；保存的根仍可见时保持展开，消失或被隐藏后选择当前首个可见根。没有可见根时保留原展开/全部折叠选择，重新显示后恢复。存储不可用或内容无效时显示提示，页面仍可展开与折叠。节点是 task，箭头 `A → B` 表示 B 依赖 A。支持缩放、平移和适应画布；节点可通过鼠标和键盘打开。图工具栏提供“全屏查看”，使当前图铺满浏览器可用视口；“退出全屏”或 Esc 返回原条目，保留当前缩放、平移和节点。全屏期间背景不可交互，Tab 在图内循环；退出后焦点回到全屏按钮。全屏内可打开详情，详情关闭后返回原图节点；Esc 先关闭详情，再退出全屏。全屏状态不持久化，窄屏仍可访问按钮和画布。 |
| W6 | 展开图包含根及其所有后续任务。共享后续任务可在多个根的图中出现，但同一张图内只出现一次。图中同时显示来自其他任务链的直接前置节点，并明确标记“外部前置，上游已省略”。 |
| W7 | 待处理、进行中、已完成分别使用灰、蓝、绿，并附文字；阻塞用独立标记表达，不增加新的 task 状态。必须保留已完成的前置节点，不能按状态筛掉依赖。 |
| W8 | 点击独立任务条目或任意图节点打开同一个详情侧栏，展示完整标题、描述、全部 PR 引用、附件区域、状态、ID、创建与更新时间、全部直接前置、未完成前置和直接后续；依赖引用可以继续打开对应任务。详情通过已有详情 API 读取，读取失败可局部重试；附件列表、写操作与预览有独立状态，不修改图快照。 |
| W9 | 加载中、没有项目、没有任务、项目不存在、请求失败和图规模超限均有明确页面。失败不得显示成零任务。提供手动刷新；成功后整体替换项目快照。当前类别没有条目、当前类别全部完成且默认隐藏、项目没有任务分别有明确空态；全部完成空态提供显示入口，显示入口将焦点移至仍保留的复选框。 |
| W10 | 使用本机服务的同一个 origin，生产环境不依赖额外前端服务或 CDN。保持服务端现有 loopback 监听约束；集成现有 `deployment/localhost`，同一启动入口拉起完整页面、API 和 PostgreSQL。 |
| W11 | CI 真实校验新增功能：Go 总语句覆盖率与 web 总语句覆盖率分别严格大于 90%，同时保留已有 Go package/function/critical-block 门槛和原生 CLI 检查。 |
| W12 | 详情侧栏支持 Esc、关闭按钮、焦点约束及关闭后的焦点恢复；附件表单及同源预览 frame 的键盘操作保持该侧栏生命周期。320px 宽屏幕仍可访问主要内容，图内允许滚动，页面不产生整体横向溢出。 |

## 统计与共享任务

```text
total = todo + inProgress + done
todo = ready + blocked
blocked = status 为 todo 且至少一个直接前置未完成的任务数
完成比例 = done / total；total 为 0 时展示“暂无任务”
```

“待处理”包含“可开始”和“被阻塞”，后三者不能相加作为总数。进行中、已完成的任务不计入待处理，即使依赖关系发生变化也以服务端规则和投影为准。

独立任务不显示单节点任务图，也不显示 0/1 式链进度。任务链数是非独立根的数量，不是连通分量数，不能与独立任务数相加作为项目任务总数。

每个任务链根条目的进度仅计算该根与其下游可达任务，按 ID 去重，不计算额外展示的外部前置。共享任务使不同根条目的进度分母存在交集，各条目的数字不能相加作为项目总数。

## 一致性与读取边界

成功的项目图响应必须包含完整图和同一快照中的统计。不得把现有任务列表的多个分页响应当作共同快照，也不得用筛选后的列表推断根节点。

切换项目或选中任务时立即显示新资源的加载状态，不短暂显示旧资源内容；仅同一资源的刷新允许保留上次成功数据。

节点详情是点击时的最新读取，不承诺与此前图快照处于同一时刻。详情的状态、依赖、阻塞或更新时间与画布数据不一致时，提示“任务信息已有变化，刷新任务图”，避免局部更新后产生错误的全图统计。PR 属性随完整详情读取，属性更新沿用 task 的更新时间；图响应不携带属性。

MVP 支持一个项目最多 1,000 个节点、5,000 条依赖边。这是产品保护上限；固定拓扑的生产验收不保证任意 DAG 都具有相同耗时。超过任一上限时显示规模和限制，拒绝返回部分图或部分统计。项目及任务仍可通过既有 API 管理。

## PR 引用展示

详情在描述后显示“关联 PR”总数量及按序排列的标题/URL，保留完整数据与重复项。
本地每页最多挂载 100 项，超过时提供范围/总数及前后页、直接页码选择；分页不
重新请求 API，任务或集合替换回第一页并保持可访问焦点。空列表有明确空态，
空字符串用展示性标记表达，长文本自动换行；完整属性的格式与原值语义由
[属性需求](daynight-task-properties.md)拥有。所有字符串作为文本呈现；浏览器能
识别的绝对 HTTP(S) 地址提供隔离的新标签页链接，其他值仍可查看和选择，不作为
HTML 或脚本执行。页面展示不改变 server 对字符串的接受规则，不抓取 PR 内容。

## 附件区域

附件区域位于关联 PR 之后。每次选择一个文件，默认目标路径为该文件名，用户可以
修改为多层相对路径；相同路径直接覆盖。目录由完整文件路径形成，文件提供下载和
删除。加载、上传、删除及预览错误局部展示，续页失败保留已读取文件并明确标记列表
不完整；用户可以重试或手动刷新。切换 task、文件或关闭侧栏时，过期请求不能覆盖
当前选择。修改成功及刷新发现同路径 `updatedAt` 变化时重新读取所选内容。

Markdown 按 CommonMark 和 GFM（包括表格）渲染，原始 HTML 作为文本显示；相对
图片与链接按文档目录指向 task 预览路径，独立 `#fragment` 保留。图片、PDF、文本、
HTML 和其他格式的展示及可信同源执行约定由[附件需求](daynight-task-attachments.md#web-管理与预览)
拥有。HTML/PDF 的可用性错误与重试在原生 frame 加载前展示，frame 内的资源继续按
浏览器规则加载；预览没有独立弹窗、会话或隔离执行机制。

## 部署与测试隔离

日常部署继续使用 `deployment/localhost`，完整应用一并启动，正常重建保留项目及任务数据。测试使用独立的 `deployment/dev-ci`，复用相同生产镜像构建和转发配置，在专用项目、端口、数据库、卷与网络中执行；不修改日常 localhost 环境。

测试正常完成、失败或取消均清理本次资源，其他运行和日常数据保持可用。清理失败必须使验收失败，并保留诊断与原始测试结果。子命令进程组在主进程退出后
仍归当前 run 管理，清理必须终止遗留后代；中断恢复只接受已有回执的有效 run ID，
并保留原始回执。Go 与 web 的覆盖率规则不变。

源码构建使用固定 Node/pnpm 依赖生成真实页面，缺少产物时 Go 构建必须失败。
Docker 构建完成相同流程，宿主机只需 Docker；最终运行镜像不依赖 Node。HTML、
完整图和最新详情禁用缓存，哈希静态资源使用长期 immutable 缓存。未知 API 返回
JSON 404，缺失资源、资源目录与未知页面不得回退到 SPA HTML。

## 明确延后的能力

| 能力 | 当前体验 | 后续增加所需工作 |
|---|---|---|
| 创建、编辑任务，拖线改依赖 | 任务字段和依赖图只有读取与导航操作；附件独立管理 | 使用已有写 API，增加表单、version 冲突处理和全图刷新；图组件不负责领域校验。 |
| 自动刷新、SSE、WebSocket | 显示最近成功刷新时间，由用户手动刷新 | 替换数据获取触发方式，继续整体应用完整快照。 |
| 登录、多用户、远程部署 | 当前仅本机 loopback 使用，尚未实现鉴权 | 按[鉴权需求](daynight-auth.md)及[架构](../design/daynight-auth.md)交付登录和项目权限，保留可信同源预览；完成前不能直接放宽监听地址。 |
| 搜索、图内节点状态筛选、跨项目关系 | 页签按完整图拓扑分类，各类按完成度选择条目，展开图保留完整依赖 | 增加保持前置上下文的搜索投影；不直接删除不匹配节点。 |
| 按连通分量重新分组任务链 | 共享后续仍可出现在多个根链中 | 另加分组投影和浏览交互；分类与页签状态保持独立于根投影，不能以页签拆分改变既有共享语义。 |
| 超大图与持久化布局 | 超限时明确拒绝图展示 | 测量后调整上限，或另设具有闭包语义的分图 API；不得静默截断。 |

## 验收

验收至少包含：页签首次默认与按项目恢复、完整图独立分类（包括已完成前置、依赖增删后的重新归类）、页签数量与完整统计、独立行直接详情、两类独立完成筛选和浏览位置、切换页签保留展开选择、单一类别为空、两类全部完成、三个根共享后续、菱形依赖、多个外部前置、独立任务、根已完成而后续未完成的整链状态、全部待处理、零完成但已有进行中任务、全部完成、共享后续去重与外部前置不计入整链状态、刷新后的整链状态转换、空项目、长标题与中文、超过一页的项目、真实接口失败与重试、切换页面时旧请求晚到、直接地址刷新、展开与全部折叠的跨刷新保留、项目隔离、空图变为非空图、浏览器存储失败、完成链显示偏好的跨刷新/项目保留、全部完成空态与焦点、隐藏当前图后详情与完整统计保留、全屏进入与退出、缩放和平移保留、全屏内详情及分层 Esc、背景焦点隔离、窄屏全屏尺寸以及键盘访问。

交互预览使用固定数据验证设计；功能交付须用生产构建页面、真实服务进程和隔离 PostgreSQL 数据验证完整路径。
附件功能在原生和生产容器两个目标上让已安装 CLI 与页面交叉操作同一 task 文件，
原始二进制按字节比较；PDF 必须由实际 compositor 截图验证预期页面色块已绘制，
HTML 相对资源通过可见交互验证。新增附件场景仅允许精确 task/file PUT/DELETE，
原有图功能场景继续只读。每次完整运行复用一次 CLI 安装并核对源码与产物回执，
`project-view-tabs` 在两个目标上验证页签、分类、详情、独立筛选及浏览偏好。严格 inventory 为原生 14 个、容器 10 个唯一场景，包含原有四个原生容量/超限检查。原生二进制与生产容器 gateway 都必须验证项目、图、详情和失败恢复；容量验收在固定 Linux CI 浏览器与原生生产进程上执行。规模上限内的图必须通过[设计中的性能验收](../design/daynight-web.md#验证与-ci)：固定 CI 浏览器五次展开的最慢一次不超过 3,000ms，布局后节点与视口操作反馈不超过 300ms。网络读取单独计时，上限必须以实际验收结果确认。

PR 根据[CI 路由](../../README.md#ci-selection)选择受影响模块，main push 执行全量检查。选中的 web job 内，验收场景不得接受跳过、重试后成功、flaky、缺少指定场景或不完整截图/计时回执；未选中的模块 job 必须为 `skipped`，不产生该模块的验收结论。

CI 回执必须来自干净测试源码且等于对应 `GITHUB_SHA`，保留生产二进制与容器镜像身份；本机浏览器覆盖不能冒充锁定 CI 浏览器的性能结论。

现有生产浏览器 inventory 验证看板基线。附件前端 mockup 使用实际组件、CSS 和内存
fixture，不依赖 Go/PG，其外观、状态和焦点探针不能证明真实后端旅程。
[A-T6](../design/daynight-task-attachments-tasks.md#a-t6)拥有新增附件生产浏览器场景、
安装 CLI 与服务的组合验收及对应 CI inventory；保留现有看板性能与覆盖率门槛，
不为附件增加新的性能门槛。
