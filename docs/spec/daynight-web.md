## 目标与使用环境

通过本机浏览器查看 `daynight-server` 中的项目、任务进度和执行依赖。完整路径为：项目列表 → 项目详情 → 独立任务列表或任务链 → 查看任务详情。

沿用[服务端要求](daynight-server.md)的 project、task 和依赖语义。“根任务”是没有前置依赖的 task；“后续任务”是沿执行方向可达的 task，不引入父子任务模型。独立任务在完整图中既没有前置也没有后续；任务链页签沿用根任务投影，只包含有后续的根。分类取决于依赖关系，已完成前置不会让后续变成独立任务。页面展示已有数据；项目与任务的创建、修改继续使用现有 API。

## 统计与共享任务

```text
total = proposed + todo + inProgress + done
todo = ready + blocked
blocked = status 为 todo 且至少一个直接前置未完成的任务数
完成比例 = done / total；total 为 0 时展示“暂无任务”
```

“待处理”包含“可开始”和“被阻塞”，后三者不能相加作为总数。待审批、进行中、
已完成的任务不计入待处理。待审批即使有未完成前置也不计入被阻塞，`blockedBy`
仍保留未完成的直接前置；其 `ready` 始终为 false。创建默认为 proposed，审批后为
todo，仍有未完成前置时显示待处理及其阻塞状态。审批不领取任务，也不完成任何前置。
[生命周期决策](../../.agents/notes/implemented/feature/2026-10-22-task-approval-lifecycle.md)拥有审批及专用操作的规则。

独立任务不显示单节点任务图，也不显示 0/1 式链进度。列表工具栏中的任务链条目数是非独立根的数量，不是连通分量数；工具栏继续显示可见/全部条目数。页签数字统计未完成任务，两者相加等于项目待审批数、待处理数与进行中数之和；链页签的数字不表示根条目数。

每个任务链根条目的进度和聚合状态仅计算该根与其下游可达任务，按 ID 去重，不计算额外展示的外部前置。递归上下文只补齐前置，不扩大链内主体。共享任务使不同根条目的进度分母存在交集，各条目的数字不能相加作为项目总数。

## 渐进图生命周期

画布保存实际可见 S，不持久化，项目/根/页签变化或卸载后清除。显式展开重新布局，在当前缩放居中操作卡片并聚焦主体；reset 重算概览并 framing，焦点保留 reset 控件。成功刷新保留仍属于新 P 的实际可见 ID，加根后只保留诱导无向图的根连通分量，不自动加入新基线或新任务；刷新保持视口，失败保持旧数据/S/视口。重置/remount 才计算新概览。打开详情时刷新不抢焦点，消失入口使用原关闭回退。详情、附件面板、请求及 locale 生命周期保持，语言变化只重译新控件/计数。

后续依赖检查目标由[任务检查要求](daynight-task-inspection.md) TI3–TI5 拥有；主体高亮、独立 Details 和曲线不属于当前概览交付事实。

## 一致性与读取边界

成功的项目图响应必须包含完整图和同一快照中的统计。不得把现有任务列表的多个分页响应当作共同快照，也不得用筛选后的列表推断根节点。

切换项目或选中任务时立即显示新资源的加载状态，不短暂显示旧资源内容；仅同一资源的刷新允许保留上次成功数据。定时读取仅覆盖当前项目完整图与打开的任务详情，项目列表、附件列表及内容继续使用各自的刷新和写入后更新机制。页面隐藏不取消已发出的请求；重新可见时若已有图读取则沿用它。手动刷新立即取代当前图读取，自动时钟不会中断它。详情刷新期间保留同一任务的正文；已有详情请求未完成时合并一次后续读取。页面隐藏时详情自动读取与排队的后续读取等待，已发出的请求可以完成。首次读取失败后自动重试仍保留错误，直到成功恢复。

节点详情在打开时读取，并随每次成功图读取再次更新，不承诺与此前图快照处于同一时刻。详情的状态、依赖、阻塞或更新时间与画布数据不一致时，提示“任务信息已有变化，刷新任务图”，避免局部更新后产生错误的全图统计。PR 属性随完整详情读取，属性更新沿用 task 的更新时间；图响应不携带属性。

MVP 支持一个项目最多 1,000 个节点、5,000 条依赖边。这是产品保护上限；固定拓扑的生产验收不保证任意 DAG 都具有相同耗时。超过任一上限时显示规模和限制，拒绝返回部分图或部分统计。项目及任务仍可通过既有 API 管理。

## 审批与读写一致性

审批按钮仅在完整详情已读取为 proposed、没有进行中提交或未核对结果，并且没有
已知信息差异、读取错误或必需核对时可用。成功观察后，描述符不变的可选周期 GET
不废弃该精确版本，也不因网络仍在 refreshing 而阻断显式批准。状态、标题、更新时间、
ready、前置或阻塞集合的已知变化要求重新读取；前置变化不必修改任务自身版本。
图 receipt 序号不等于任务元数据版本，不能据此虚报已读内容或导致审批长期不可用。
图投影没有 version，不得从图发起写入。详情 version 使用正 int64 数字的精确十进制
值，读取、内部保存及 POST 期间不能经过会舍入的 Number；覆盖安全整数上限以上与
int64 最大值，非法值整体拒绝。服务成功响应须对应原 project/task、todo 及预期新版本。

提交期间保留任务说明、附件、前置和图上下文，禁用重复激活并用可访问状态反馈。
关闭或切换详情不会释放该任务的提交防重状态。成功立即使用确认的 todo 详情并移除
审批按钮，再整体刷新图，使统计、节点、条目和整链状态收敛。刷新失败沿用可见的旧
快照提示并可显式刷新，不将已批准详情还原为 proposed。开始于审批前的详情或图请求
不能覆盖该确认结果。

版本冲突保留错误并重新读取当前详情和完整图。若仍为 proposed，用户审阅新内容后
重新点击；若其他调用方已推进生命周期，则展示实际当前状态并移除批准动作。超时、取消、5xx、响应丢失
或无法确认响应时先读取当前任务；核对未完成时说明结果未知，保留真实错误并提供
状态刷新，不启用新的提交。核对返回 404 时清除任务正文、附件面板和批准入口，
仍显示结果未知、原写入错误和本次读取错误；核查与重试只执行 GET，不再发批准。
浏览器取消不表示服务事务已回滚。晚到结果只归属于原
project/task，不能替换另一个任务或触发另一轮审批。显式鉴权壳还将会话限定在当前
用户与身份 generation；相同身份导航保留操作，身份切换或会话失效清除旧内容，晚到
结果不能显示在新身份下。此行为不改变生产鉴权尚未统一启用的状态。

生产组件的[浏览夹具](../../packages/daynight-web/tests/mockups/browsing.html)拥有最终
审批样式与纯前端场景；Task、独立行和全屏图复用同一详情。验收覆盖无阻塞与有阻塞
审批、防重、成功、服务失败、同版本竞争、他人批准、结果未知、图刷新失败和任务切换，
并检查英语/简体中文、桌面/320px、键盘和状态播报。此夹具不替代真实服务验收。

## PR 引用展示

详情在描述后显示“关联 PR”总数量及按序排列的标题/URL，保留完整数据与重复项。
本地每页最多挂载 100 项，超过时提供范围/总数及前后页、直接页码选择；分页不
重新请求 API，任务切换或有序集合内容变化时回第一页并保持可访问焦点。相同内容的
刷新保留当前页及焦点。空列表有明确空态，
空字符串用展示性标记表达，长文本自动换行；完整属性的格式与原值语义由
[属性需求](daynight-task-properties.md)拥有。所有字符串作为文本呈现；浏览器能
识别的绝对 HTTP(S) 地址提供隔离的新标签页链接，其他值仍可查看和选择，不作为
HTML 或脚本执行。页面展示不改变 server 对字符串的接受规则，不抓取 PR 内容。

## 描述与附件引用

`description` 按 CommonMark/GFM 展示标题、段落、列表、引用、代码块、表格、链接和
图片；原始 HTML 作为文本显示，URL 协议处理沿用附件 Markdown 的规则。空字符串
显示当前语言的“暂无描述”。标题和仓库地址继续作为文本显示。Markdown 表格与
代码块在各自区域横向滚动，长描述在 320px 下换行，页面不产生整体横向溢出。
API 存储与 CLI/Agent 读取保留原始字符串字节，不增加格式标记或改写已有描述。

描述中的相对链接和图片以当前任务附件根为基准；附件 Markdown 仍以文件所在目录
为基准，路径不能越过任务根。普通主键激活不带 query/hash 的有效相对附件链接时，
激活现有附件页签、通过同一个附件控制器选中文件并将预览带入焦点。链接保留真实
预览 URL；修饰键、非主键、上下文菜单、绝对/协议/根相对 URL、独立 fragment 以及
query/hash 链接保留现有 URL 策略与原生导航。本文不要求生成 Markdown 标题锚点。

只有完整分页清单才能判定文件缺失。加载、清单失败、非法路径、确认缺失与预览
失败分别显示；适用时提供重试。描述导航不能建立第二个清单或预览所有者。切换
任务、关闭详情及鉴权/资源失效取消旧请求，晚到响应不能改变当前身份；同路径覆盖
继续遵守附件 revision 与刷新规则。详细要求由[任务阅读要求](daynight-task-inspection.md)
TI8–TI11 拥有。

## 附件区域

附件页签位于任务公共标题下，与概览并列；左右分屏在 320px 窄屏继续保留。左侧是
目录树、刷新与上传，右侧是所选文件预览及其下载、新标签页打开、删除操作。概览保留描述、关联 PR、
关系与元数据。隐藏面板不参与键盘导航，切换页签保留选择、目录、预览和上传草稿；
切换 task/project 则重置页签和旧身份状态。每次选择一个文件，默认目标路径为该
文件名，用户可以修改为多层相对路径；相同路径直接覆盖。目录由完整文件路径形成。
加载、上传、删除及预览错误局部展示，续页失败保留已读取文件并明确标记列表
不完整；用户可以重试或手动刷新。切换 task、文件或关闭详情时，过期请求不能覆盖
当前选择。修改成功及刷新发现同路径 `updatedAt` 变化时重新读取所选内容。

Markdown 按 CommonMark 和 GFM（包括表格）渲染，原始 HTML 作为文本显示；相对
图片与链接按文档目录指向 task 预览路径，独立 `#fragment` 保留。图片、PDF、文本、
HTML 和其他格式的展示及可信同源执行约定由[附件需求](daynight-task-attachments.md#web-管理与预览)
拥有。Markdown、文本/JSON/源码和大图仅由预览正文纵向滚动；HTML/PDF 仅由
占满正文的原生 frame 内文档或阅读器纵向滚动。对话框和右侧预览外壳不再叠加纵向
滚动，预览标题及操作始终可访问；844×390 短视口压缩间距以保留可用内容。HTML/PDF
的可用性错误与重试在原生 frame 加载前展示，frame 内的资源继续按浏览器规则加载；
HEAD 成功不能证明实际内容已经绘制。预览没有独立弹窗、会话或隔离执行机制。
独立阅读入口紧邻下载，链接到当前文件的完整页面，使用 `_blank` 与
`noopener noreferrer`，不改变来源详情。完整页面通过现有完整分页清单确认精确
文件路径，区分加载、不完整清单、请求失败、确认缺失与预览失败；沿用同一渲染器、
相对资源及文件接口。独立阅读使用普通键盘行为和语言选择，正文与原生 frame
分别沿用唯一滚动所有者，不安装模态键盘桥。产品要求由
[独立页面完整阅读](daynight-task-attachments.md#独立页面完整阅读)拥有。
完整阅读及本阅读任务组的独立真实服务运行时验收已完成；实际源码、产物、环境与
清理回执由[附件组合验收决策](../../.agents/notes/implemented/testing/2026-10-21-task-attachment-cross-layer-acceptance.md)
指定的任务与 PR/CI 证据拥有，不将本机浏览器结果扩大为托管 CI 结论。

## 部署与测试隔离

日常部署继续使用 `deployment/localhost`，完整应用一并启动，正常重建保留项目及任务数据。测试使用独立的 `deployment/dev-ci`，复用相同生产镜像构建和转发配置，在专用项目、端口、数据库、卷与网络中执行；不修改日常 localhost 环境。

测试正常完成、失败或取消均清理本次资源，其他运行和日常数据保持可用。清理失败必须使验收失败，并保留诊断与原始测试结果。子命令进程组在主进程退出后
仍归当前 run 管理，清理必须终止遗留后代；中断恢复只接受已有回执的有效 run ID，
并保留原始回执。Go 与 web 的覆盖率规则不变。

源码构建使用固定 Node/pnpm 依赖生成真实页面，缺少产物时 Go 构建必须失败。
Docker 构建完成相同流程，宿主机只需 Docker；最终运行镜像不依赖 Node。HTML、
完整图和最新详情禁用缓存，哈希静态资源使用长期 immutable 缓存。未知 API 返回
JSON 404，缺失资源、资源目录与未知页面形状不得回退到 SPA HTML。已登记页面形状
中的无效 ID 沿用 index 加前端未找到页面的行为；附件原始路径守卫先拒绝非法路径。

交互预览使用固定数据验证设计；功能交付须用生产构建页面、真实服务进程和隔离 PostgreSQL 数据验证完整路径。
附件功能在原生和生产容器两个目标上让已安装 CLI 与页面交叉操作同一 task 文件，
原始二进制按字节比较；PDF 必须由实际 compositor 截图验证预期页面色块已绘制，
HTML 相对资源通过可见交互验证。新增附件场景仅允许精确 task/file PUT/DELETE，

`project-view-tabs` 在两个目标上验证页签、分类、详情、独立筛选及浏览偏好。当前严格 inventory 为原生 22 个、容器 17 个唯一场景，共 39 个；两个目标各有 17 个功能场景，原生另有五个容量/超限检查。三个双语场景保持，`task-approval`、`task-approval-conflicts`、`task-approval-recovery` 覆盖 W13 的审批、冲突与结果核对。审批场景只允许已登记 project/task 的 POST approve 与精确请求次数。`task-description-markdown` 覆盖 CommonMark/GFM 展示与同一附件控制器导航；该场景浏览器只执行 GET/HEAD，资料通过已安装 CLI 或 API request context 准备。

PR 根据[CI 路由](../../README.md#ci-selection)选择受影响模块，main push 执行全量检查。选中的 web job 内，验收场景不得接受跳过、重试后成功、flaky、缺少指定场景或不完整截图/计时回执；未选中的模块 job 必须为 `skipped`，不产生该模块的验收结论。

CI 回执必须来自干净测试源码且等于对应 `GITHUB_SHA`，保留生产二进制与容器镜像身份；本机浏览器覆盖不能冒充锁定 CI 浏览器的性能结论。

fixture，不依赖 Go/PG，其外观、状态和焦点探针不能证明真实后端旅程。
