# 项目与任务看板

状态：完整图 API、只读项目任务看板及 localhost/dev-ci 单服务交付已实现；保留完整路线与原生箭头的长虚线绘制修复已通过完整本地生产与固定性能验收，待当前源码的真实 CI、review 与交付。历史验证结果由[验收报告](../research/daynight-web-acceptance.md)记录。本文定义只读 MVP 的交付要求；[设计](../design/daynight-web.md)说明实现方式与任务顺序，[交互预览](../design/mockups/task-dashboard.html)用于确认视觉与操作，[任务清单](../design/daynight-web-tasks.md)记录实现范围和完成条件。

## 目标与使用环境

通过本机浏览器查看 `daynight-server` 中的项目、任务进度和执行依赖。完整路径为：项目列表 → 项目详情 → 展开任务链 → 查看任务详情。

沿用[服务端要求](daynight-server.md)的 project、task 和依赖语义。“根任务”是没有前置依赖的 task；“后续任务”是沿执行方向可达的 task，不引入父子任务模型。页面展示已有数据；项目与任务的创建、修改继续使用现有 API。

## 必须交付的行为

| 编号 | 要求 |
|---|---|
| W1 | `/` 列出项目名称、仓库地址和创建时间。使用已有游标分页，提供“加载更多”；所有项目都可访问。未加载的项目不得算入全局统计，页面不展示假定完整的项目总数。 |
| W2 | 点击项目进入 `/projects/{projectId}`；直接打开或刷新此地址得到同一项目页面，并能返回项目列表。 |
| W3 | 项目顶部显示任务总数、已完成、待处理、进行中、可开始和被阻塞数量，以及完成比例。所有数字来自一个完整项目快照，按任务 ID 去重。 |
| W4 | 每个根任务显示一个条目，包含根任务标题、执行状态和其任务链的完成进度。根任务已完成不代表整条任务链已完成。独立任务也是一个条目。 |
| W5 | 点击条目展开横向有向图；同时最多展开一个条目。节点是 task，箭头 `A → B` 表示 B 依赖 A。支持缩放、平移和适应画布；节点可通过鼠标和键盘打开。 |
| W6 | 展开图包含根及其所有后续任务。共享后续任务可在多个根的图中出现，但同一张图内只出现一次。图中同时显示来自其他任务链的直接前置节点，并明确标记“外部前置，上游已省略”。 |
| W7 | 待处理、进行中、已完成分别使用灰、蓝、绿，并附文字；阻塞用独立标记表达，不增加新的 task 状态。必须保留已完成的前置节点，不能按状态筛掉依赖。 |
| W8 | 点击任意节点打开详情侧栏，展示完整标题、描述、状态、ID、创建与更新时间、全部直接前置、未完成前置和直接后续；引用可以继续打开对应任务。详情通过已有详情 API 读取，读取失败可局部重试。 |
| W9 | 加载中、没有项目、没有任务、项目不存在、请求失败和图规模超限均有明确页面。失败不得显示成零任务。提供手动刷新；成功后整体替换项目快照。 |
| W10 | 使用本机服务的同一个 origin，生产环境不依赖额外前端服务或 CDN。保持服务端现有 loopback 监听约束；集成现有 `deployment/localhost`，同一启动入口拉起完整页面、API 和 PostgreSQL。 |
| W11 | CI 真实校验新增功能：Go 总语句覆盖率与 web 总语句覆盖率分别严格大于 90%，同时保留已有 Go package/function/critical-block 门槛和原生 CLI 检查。 |
| W12 | 详情侧栏支持 Esc、关闭按钮、焦点约束及关闭后的焦点恢复。320px 宽屏幕仍可访问主要内容，图内允许滚动，页面不产生整体横向溢出。 |

## 统计与共享任务

```text
total = todo + inProgress + done
todo = ready + blocked
blocked = status 为 todo 且至少一个直接前置未完成的任务数
完成比例 = done / total；total 为 0 时展示“暂无任务”
```

“待处理”包含“可开始”和“被阻塞”，后三者不能相加作为总数。进行中、已完成的任务不计入待处理，即使依赖关系发生变化也以服务端规则和投影为准。

每个根条目的进度仅计算该根与其下游可达任务，按 ID 去重，不计算额外展示的外部前置。共享任务使不同根条目的进度分母存在交集，各条目的数字不能相加作为项目总数。

## 一致性与读取边界

成功的项目图响应必须包含完整图和同一快照中的统计。不得把现有任务列表的多个分页响应当作共同快照，也不得用筛选后的列表推断根节点。

切换项目或选中任务时立即显示新资源的加载状态，不短暂显示旧资源内容；仅同一资源的刷新允许保留上次成功数据。

节点详情是点击时的最新读取，不承诺与此前图快照处于同一时刻。详情的状态、依赖、阻塞或更新时间与画布数据不一致时，提示“任务信息已有变化，刷新任务图”，避免局部更新后产生错误的全图统计。

MVP 支持一个项目最多 1,000 个节点、5,000 条依赖边。这是产品保护上限；长虚线绘制修复已通过固定拓扑的完整本地性能矩阵，当前源码的 hosted 验证仍待通过，且不能推断任意 DAG 都具有相同耗时。超过任一上限时显示规模和限制，拒绝返回部分图或部分统计。项目及任务仍可通过既有 API 管理。

## 部署与测试隔离

日常部署继续使用 `deployment/localhost`，完整应用一并启动，正常重建保留项目及任务数据。测试使用独立的 `deployment/dev-ci`，复用相同生产镜像构建和转发配置，在专用项目、端口、数据库、卷与网络中执行；不修改日常 localhost 环境。

测试正常完成、失败或取消均清理本次资源，其他运行和日常数据保持可用。清理失败必须使验收失败，并保留诊断与原始测试结果。子命令进程组在主进程退出后
仍归当前 run 管理，清理必须终止遗留后代；中断恢复只接受已有回执的有效 run ID，
并保留原始回执。Go 与 web 的覆盖率规则不变。

源码构建使用固定 Node/pnpm 依赖生成真实页面，缺少产物时 Go 构建必须失败。
Docker 构建完成相同流程，宿主机只需 Docker；最终运行镜像不依赖 Node。HTML、
完整图和最新详情禁用缓存，哈希静态资源使用长期 immutable 缓存。未知 API 返回
JSON 404，缺失资源、资源目录与未知页面不得回退到 SPA HTML。

## 明确延后的能力

| 能力 | 当前体验 | 后续增加所需工作 |
|---|---|---|
| 创建、编辑任务，拖线改依赖 | 页面只有读取与导航操作 | 使用已有写 API，增加表单、version 冲突处理和全图刷新；图组件不负责领域校验。 |
| 自动刷新、SSE、WebSocket | 显示最近成功刷新时间，由用户手动刷新 | 替换数据获取触发方式，继续整体应用完整快照。 |
| 登录、多用户、远程部署 | 仅本机 loopback 使用 | 重新设计身份、授权和部署边界；不能直接放宽监听地址。 |
| 搜索、状态筛选、跨项目关系 | 完整展示所选项目依赖图 | 增加保持前置上下文的搜索投影；不直接删除不匹配节点。 |
| 超大图与持久化布局 | 超限时明确拒绝图展示 | 测量后调整上限，或另设具有闭包语义的分图 API；不得静默截断。 |

## 验收

验收至少包含：三个根共享后续、菱形依赖、多个外部前置、独立任务、根已完成而后续未完成、全部完成、空项目、长标题与中文、超过一页的项目、真实接口失败与重试、切换页面时旧请求晚到、直接地址刷新以及键盘访问。

交互预览使用固定数据验证设计；功能交付须用生产构建页面、真实服务进程和隔离 PostgreSQL 数据验证完整路径。原生二进制与生产容器 gateway 都必须验证项目、图、详情和失败恢复；容量验收在固定 Linux CI 浏览器与原生生产进程上执行。规模上限内的图必须通过[设计中的性能验收](../design/daynight-web.md#验证与-ci)：固定 CI 浏览器五次展开的最慢一次不超过 3,000ms，布局后节点与视口操作反馈不超过 300ms。网络读取单独计时，上限必须以实际验收结果确认。必选检查不得接受跳过、重试后成功、flaky、缺少指定场景或不完整截图/计时回执。CI 回执必须来自干净测试源码且等于对应 `GITHUB_SHA`，保留生产二进制与容器镜像身份；本机浏览器覆盖不能冒充锁定 CI 浏览器的性能结论。
