# 任务执行耗时与卡住提醒需求

本文定义任务执行耗时、项目提醒阈值与 Task 卡片的可观察行为。
[架构](../design/daynight-task-timing.md)拥有存储、时钟与界面机制，
[任务拆分](../design/daynight-task-timing-tasks.md)拥有交付边界。
本组是已采用的交付设计；运行时实现和整体验收以对应 Daynight 任务及实际合并结果为准。

## TT1：计时含义

执行耗时是最后一次实际进入 `in_progress` 到当前时间或进入 `done` 的墙钟时间。
进行中的任务持续显示耗时；完成时固定结果。早先尝试不累加，普通字段编辑不重置计时。
计时不表示 CPU 时间、人工有效工作时间或持续收到进度信号的时间。

当前公开生命周期由 `approve`、`claim`、`complete` 提供
`proposed → todo → in_progress → done`；普通更新不能修改状态。
计时功能保留这些限制，不增加重新打开、直接完成或重复 claim 的入口。
若存储中发生新的合法 `in_progress` 进入，起点替换而非累加；当前调用者仍须遵守既有生命周期。

## TT2：起止时间与一致性

服务端生成 `startedAt` 与 `completedAt`，客户端不能提交或修改它们。
成功 claim 记录真实开始，成功 complete 记录真实完成；修改标题、描述、依赖和 PR 属性保留起止时间。
状态、时间和任务版本在同一事务提交。版本冲突、无效转换、未完成前置、权限拒绝、取消或数据库失败均不能留下部分计时更新。

完成后的耗时不随时间、后续字段编辑、页面刷新或服务重启增长。
公开资源保留可空起止字段：新建、尚未执行及缺失历史事实的任务使用 `null`。
迁移不得从 `createdAt`、`updatedAt`、部署时间或页面首次读取时间推算起点。
缺少真实起点时不显示耗时，也不根据耗时触发提醒。迁移后的旧执行任务完成时可以记录真实终点，但不能因此产生推算耗时。

## TT3：项目提醒阈值

每个项目有独立的正整数分钟阈值 `executionWarningMinutes`，默认 `60`，旧项目通过迁移获得相同默认值。
项目设置页提供有明确分钟单位的编辑框、保存、取消及保存状态。保存后的值跨客户端、刷新和服务重启保持一致。
修改项目 A 不影响项目 B，也不改变任务的开始或完成时间。

项目成员可读取设置，仅项目管理员可修改。非成员沿用项目资源隐藏规则。
修改须使用读取时的精确设置版本；过期提交返回冲突，即使数值恰好相同也不报告成功。
成功的同值保存保留版本，实际变化增加版本。
缺失、`null`、非整数、零、负数、超出支持整数范围及未知字段必须返回明确错误。
草稿、取消、失败或冲突均不能改变卡片使用的已保存阈值。
冲突后读取并展示权威值，由编辑者重新决定，不自动覆盖或重发。

## TT4：实时显示与提醒

任务处于 `in_progress` 且已知起点时，Task 卡片自动更新耗时。
仅当未舍入的实际耗时**严格大于**本项目已保存阈值时，显示醒目的
“可能卡住了” / “Possibly stuck” 提醒。恰好达到阈值时不提醒。
阈值从 `60` 分钟变为 `90` 分钟后，已运行 `75` 分钟的任务立即重新判断为未超时；改回 `60` 后恢复提醒。

提醒同时使用强调色、图标与文字，并提供含耗时及阈值的可访问说明。
保留原有状态和耗时；提醒只表示可能需要关注，不自动改变状态或宣告执行失败。
完成后移除提醒并保留最终耗时，即使完成耗时仍超过阈值。

实时计时不能依赖浏览器墙钟是否正确。页面保持打开时无需手动刷新即可跨过提醒边界；
隐藏页面停止无用更新，恢复可见时重新对齐服务端时间并恢复显示。
卡片计时不触发布局、平移、缩放、选择、展开或键盘焦点变化。

## TT5：展示与资源覆盖

图中 Task 卡片及独立任务行共享耗时含义和提醒规则。
任务链汇总代表多个任务，不将根任务耗时冒充整条链耗时。
完整任务资源、图任务资源和相关 CLI/Web 读取器保留它们需要的计时与项目设置字段。
不新增 CLI 设置修改命令，也不改变紧凑人类列表原有的字段选择。

保持 `220×96` 紧凑和 `220×136` 可展开卡片几何，保留独立 Details 操作、标题、共享标记、依赖检查、选择强调和展开控件。
中文、英文均覆盖耗时单位、阈值、提醒、设置说明及失败反馈。
不足一分钟必须与未知耗时可区分；分钟、小时、多天和长标题在窄屏中保持可读。
精确起点和已知终点通过提示或可访问说明提供，不逐秒播报 live region。
交互原型随设计任务提供，覆盖普通、进行中、提醒、完成、未知历史、长标题、窄屏、加载、错误、空结果及设置保存状态。

## TT6：验收边界

- 10:00 开始、10:45 完成的任务固定显示 45 分钟；编辑、刷新与重启后保持不变。
- 重复或过期生命周期请求不能重置起点或改变已提交结果；存储层的新进入替换旧起点，不累加早先尝试。
- 确定性时钟验证默认阈值下，59:59 和 60:00 不提醒，60:01 提醒；显示单位舍入不改变判断。真实服务和浏览器另行验证实际阈值跨越。
- 同一打开页面中的自动推进、后台恢复和阈值保存均能更新判断，不改变图布局和焦点。
- 管理员保存、成员只读、非成员隐藏、权限变化、冲突、无效输入、失败、取消与项目隔离均通过真实服务验证。
- 新任务、旧数据及缺少起点的任务不产生推算耗时；完成任务不显示卡住提醒。
- 使用真实 PostgreSQL、实际 CLI 读取与生产 Web 资产完成整体验收，并通过所改模块的现有检查和覆盖率门槛。
- 设计交付只确认设计与拆分；整个目标只有在全部实施任务、必要 PR 合并及整体验收完成后才算完成。
